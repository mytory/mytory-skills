이 스킬은 현재 대화 내용과 코드베이스에 대한 이해를 바탕으로 명세를 작성합니다. 사용자를 새로 인터뷰하지 말고 이미 파악한 내용을 종합하세요.

이슈 트래커와 분류 레이블의 용어를 이미 제공받았어야 합니다. 제공받지 않았다면 사용자에게 `/setup-matt-pocock-skills`를 실행하도록 안내하세요.

## 절차

1. 아직 살펴보지 않았다면 저장소를 탐색해 코드베이스의 현재 상태를 파악하세요. 명세 전반에 프로젝트의 도메인 용어집에 있는 용어를 사용하고, 변경 대상 영역의 ADR을 따르세요.

2. 기능을 테스트할 경계를 구상하세요. 새 경계를 만들기보다 기존 경계를 우선 사용하세요. 가능한 한 높은 수준의 경계를 선택하고, 새 경계가 필요하다면 가능한 한 높은 지점에 제안하세요. 코드베이스 전체의 테스트 경계는 적을수록 좋으며 이상적인 수는 하나입니다.

이 경계가 사용자의 기대와 맞는지 확인하세요.

3. 아래 템플릿으로 명세를 작성한 다음 프로젝트 이슈 트래커에 게시하세요. `ready-for-agent` 분류 레이블을 적용하세요. 추가 분류는 필요하지 않습니다.

## 구현 결정

이미 내린 구현 결정의 목록. 다음을 포함할 수 있습니다.

- 구축하거나 수정할 모듈
- 변경할 모듈 인터페이스
- 개발자가 밝힌 기술적 사항
- 아키텍처 결정
- 스키마 변경
- API 계약
- 구체적인 상호작용

구체적인 파일 경로나 코드 조각은 포함하지 마세요. 금방 오래된 정보가 될 수 있습니다.

예외: 프로토타입에서 나온 코드 조각이 상태 머신, 리듀서, 스키마, 타입 형태 등의 결정을 글보다 정확하게 표현한다면 해당 결정에 인라인으로 넣고 프로토타입에서 왔다고 간단히 밝히세요. 작동하는 데모 전체가 아니라 결정에 필요한 핵심 부분만 남기세요.
