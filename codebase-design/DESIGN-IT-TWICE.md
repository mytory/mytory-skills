# 두 번 설계하기

사용자가 선택한 심화 후보의 대안 interface를 탐색하려 할 때, 다음 병렬 하위 에이전트 패턴을 사용하세요. Ousterhout의 "Design It Twice"에 바탕을 둡니다. 첫 아이디어가 최선일 가능성은 낮습니다.

[SKILL.md](SKILL.md)의 **module**, **interface**, **seam**, **adapter**, **leverage** 용어를 사용합니다.

## 절차

### 1. 문제 공간 설명하기

하위 에이전트를 시작하기 전에 선택한 후보의 문제 공간을 사용자에게 설명하세요.

- 새 interface가 충족해야 할 제약
- 필요한 의존성과 각 의존성의 종류([DEEPENING.md](DEEPENING.md) 참고)
- 제약을 구체적으로 보여줄 간략한 코드 예시. 설계안을 제안하는 것이 아니라 제약을 이해시키기 위한 예시입니다.

사용자에게 설명을 보여준 뒤 바로 2단계로 진행하세요. 하위 에이전트가 병렬로 작업하는 동안 사용자가 내용을 읽고 생각할 수 있습니다.

### 2. 하위 에이전트 시작하기

하위 에이전트를 3개 이상 병렬로 시작하세요. 각 에이전트는 심화된 모듈에 대해 **근본적으로 다른** interface를 설계해야 합니다.

각 에이전트에게 별도의 기술 브리프를 제공하세요. 브리프에는 파일 경로, 결합 관계, [DEEPENING.md](DEEPENING.md)에 따른 의존성 종류, seam 뒤에 놓일 내용을 담으세요. 이 브리프는 1단계에서 사용자에게 보여준 문제 공간 설명과 별개입니다. 에이전트마다 다른 설계 제약을 지정하세요.

- 에이전트 1: "interface를 최소화하세요. 진입점은 최대 1~3개로 하고, 진입점당 leverage를 극대화하세요."
- 에이전트 2: "유연성을 극대화하세요. 여러 사용 사례와 확장을 지원하세요."
- 에이전트 3: "가장 흔한 호출자에 맞춰 최적화하세요. 기본 사례를 아주 간단하게 만드세요."
- 에이전트 4(해당하는 경우): "seam을 가로지르는 의존성을 위해 ports & adapters를 중심으로 설계하세요."

각 하위 에이전트가 아키텍처 용어와 프로젝트의 도메인 용어를 일관되게 사용하도록 브리프에 [SKILL.md](SKILL.md)와 GLOSSARY.md의 어휘를 모두 포함하세요.

각 하위 에이전트의 결과에는 다음을 포함하세요.

1. Interface(타입, 메서드, 매개변수와 불변 조건, 호출 순서, 오류 형태)
2. 호출자가 사용하는 방법을 보여주는 예시
3. Implementation이 seam 뒤에 숨기는 것
4. 의존성 전략과 adapter([DEEPENING.md](DEEPENING.md) 참고)
5. 득실: leverage가 높은 곳과 부족한 곳

### 3. 제시하고 비교하기

사용자가 각 설계를 이해할 수 있도록 하나씩 제시한 다음, 문장으로 비교하세요. **Depth**(interface의 leverage), **locality**(변경이 집중되는 곳), **seam의 위치**를 기준으로 차이를 설명하세요.

비교한 뒤 가장 강한 설계와 그 이유를 직접 추천하세요. 서로 다른 설계의 요소를 결합하면 좋다면 혼합안을 제안하세요. 사용자는 단순한 선택지 목록보다 분명한 판단을 원합니다.
