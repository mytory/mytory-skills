# tasteskill v2

모델의 평균적인 기본값 대신 대상에 맞는 결정을 내립니다. `scripts/draw.mjs`가 조사된 20개 방향 중 3개를 제시하면 대상에 맞는 하나를 고르고, 247개 실제 사이트에서 추출한 서체·팔레트·히어로·섹션 구도를 받습니다. 아이디어는 업종의 관습보다 대상 자체에서 찾습니다. `scripts/inspect.mjs`로 실제 브라우저에서 규칙을 측정하고, 세 너비의 스크린샷을 보고 수정합니다.

장식을 지우는 일은 절반입니다. 라벨·구분선·카드를 없앤 자리에 큰 서체, 색 면, 대상의 실제 세계를 보여주는 사진·그림, 충분한 콘텐츠를 채우세요. 절제 때문에 빈약한 페이지를 만들지 마세요.

명령의 `<skill>`은 이 스킬 폴더입니다. 프로젝트 루트에서 실행하면 작업 파일이 `.taste-skill/`에 생깁니다. Node 22+와 설치된 Chrome·Edge·Chromium이 필요하며 스크립트는 패키지를 설치하지 않습니다. `assets.mjs`는 네트워크가 필요하고 API 키는 쓰지 않습니다.

## 현재 배포본의 장면 기능 제한

원본 기준 `b9ca2fd`에는 `library/scenes.json`, 장면별 JS·CSS와 `assets/scenes/demo/`가 없습니다. `assets/scenes/`에는 공통 stage만 포함됩니다. 아래의 번들 장면 복사·데모 열기·장면 재추첨 절차는 이 파일들이 실제로 있는 배포본에서만 실행하세요. 현재는 일반 페이지·앱 방향을 뽑고 제공된 모션 예제를 직접 구현하며, 누락된 장면을 설치된 기능으로 보고하지 마세요. 장면을 직접 구현했다면 `scenes.mjs`로 검사할 수 있습니다.

## 페이지와 앱 화면

먼저 종류를 정하세요.

- **페이지**는 읽고 스크롤합니다. 랜딩·마케팅·제품 사이트, 포트폴리오, 행사, 음식점, 원페이지는 아래 실행 절차를 따릅니다.
- **앱 화면**은 업무를 처리합니다. 대시보드, 관리·분석, 설정·결제, 받은편지함·작업 대기열, 지갑, 필터 목록, 편집기·빌더는 `references/app-screens.md`를 **전부 읽고** 그 절차를 따릅니다. `draw.mjs --app`, 별도 규칙과 `inspect.mjs --app`을 사용합니다. 앱에서는 옅은 테두리·작은 라벨·반복 패널이 자연스럽지만 그라디언트·발광·색 사각형 속 아이콘·무지개 차트·지어낸 허영 지표는 피합니다. 아래 페이지 절차는 적용하지 않습니다.

앱을 소개하는 제품 사이트는 페이지입니다. 그 안의 앱 조각에는 앱 규칙을 적용하세요. 페이지의 색과 서체를 유지한 채 제품의 앱 스타일을 별도 폴더에 한 번 뽑습니다.

```bash
node <skill>/scripts/draw.mjs --app --kind <kind> --brief "<the product>" --keep palette,type --out .taste-skill/app
```

히어로의 실제 화면, 기능 확대, 차트를 모두 작동하는 앱의 일부처럼 만드세요. 패널·표·컨트롤은 `assets/app.css`, 차트는 `assets/charts.js`를 쓰고 합계가 맞는 데이터와 명확한 발견 하나를 담으세요. 페이지 설계의 이미지처럼 자르고 크기를 조절합니다. 회색 막대와 임의의 숫자 대신 실제 제품처럼 보이는 조각을 사용합니다. 랜딩과 대시보드를 함께 요청하면 각각의 절차를 따르되 팔레트와 서체는 공유하세요.

## 실행 절차

순서대로 실행하세요. 1–5단계에서 페이지의 품질이 결정됩니다.

### 1. 브리프와 프로젝트 읽기

대상, 독자, 방문자에게 요구하는 행동 하나, 기술 스택, 기존 브랜드의 색·서체·로고를 확인하세요. 특히 **실제로 확보한 이미지**를 확인합니다. 프로젝트의 사진·제품 사진, 보여줄 실제 인터페이스, 호출 가능한 이미지 생성 도구, 아무것도 없는 경우를 구분하세요. 없는 사진을 전제로 계획하지 마세요. 자체 자료가 없어도 대상의 도시·거리·재료·역사는 출처를 표시해 쓸 수 있는 공개 아카이브·박물관에 있을 수 있습니다(6단계).

모호한 요청은 해석을 한 줄로 밝히고 진행하세요. 제품 이름처럼 빠진 사실이 작업을 막을 때만 질문합니다.

그다음 메모에 **대상 고유의 요소 8–12개**를 적습니다. 이름과 뜻, 주소·문 번호·거리·동네의 타일·간판·색·서체·빛·날씨, 좌석·방·바다까지 시간·가격·연도, 월 1회 생산·겨울 휴업·예약제 같은 제약, 재료와 색, 일상과 시간, 시간표·라벨·표·간판 같은 인쇄물을 찾으세요. 이 목록이 4단계 아이디어와 6단계 이미지 검색어가 됩니다. 업종 전체의 아이디어 대신 이 고객만의 이름·거리·제약에서 출발하세요.

### 2. 주장 쓰기

디자인 전에 `references/copy.md` §1에 따라 섹션마다 주장과 증거를 한 줄씩 적으세요. 이것으로 섹션과 순서를 정합니다. 주장이 없는 섹션은 제거하세요. 히어로→로고→기능 3개→후기→가격→행동 유도의 고정 순서를 피하는 방법입니다.

### 3. 방향 뽑기

```bash
node <skill>/scripts/draw.mjs --sector <sector> --brief "<one line about the subject>" \
  --sections <roles in the order of your argument> [--tone <tone>] [--have <assets>] [--keep palette,type] \
  --options 3
```

제시된 세 방향을 고유 요소 목록과 비교하세요. 이 고객만의 특징을 담을 수 있는 구도를 선택하고 이유를 한 줄로 기록합니다. 익숙한 방향을 고르지 마세요. 맞지 않는 임의의 방향은 약한 페이지의 흔한 원인이었습니다. 선택 후 전체 시트를 뽑습니다.

```bash
node <skill>/scripts/draw.mjs <the same arguments, without --options> --direction <chosen id>
```

- `--sector`: `node <skill>/scripts/draw.mjs --list sectors`에서 가장 가까운 업종을 고릅니다.
- `--sections`: `--list roles`의 역할을 사용합니다. features, showcase, how-it-works, testimonial, proof, stats, pricing, faq, cta, footer, intro, about, work, gallery, list, contact. 히어로는 자동 포함됩니다.
- `--tone`: quiet, bold, warm, technical, playful, luxury, editorial. 브리프에 분명한 요구가 있을 때만 지정합니다.
- `--have`: **실제 확보한** 자료를 쉼표로 나열합니다. `photography`(프로젝트의 장소·사람·작업 사진), `product-photo`(해당 제품 사진 또는 생성 가능한 도구), `product-ui`(실제 스크린샷), `illustration`, `video`. 없으면 생략하세요. 공개 컬렉션에서 찾을 사진은 프로젝트 자체 사진이 아니므로 넣지 않습니다. 스크립트가 없는 자산에 의존하는 구도를 피하고 정직하게 채울 방법을 제안합니다. 소프트웨어는 HTML로 실제 인터페이스를 만들고 사진 없는 제품은 실제 세계의 사진 사이에 그림으로 표현합니다. 가짜 제품 사진을 쓰지 마세요.
- `--keep palette,type`: 기존 브랜드가 색·서체를 고정하면 사용합니다. 구도만 뽑고 역할에 브랜드 값을 매핑합니다.

출력된 **방향 시트**를 이번 구현의 아트 디렉션으로 삼으세요.

- 그대로 채택하세요. 원래 만들려던 레이아웃과 섞지 마세요.
- `--redraw hero | type | palette | photos | scenes | section:<role> | direction`은 명시된 브랜드 제약과 충돌하거나 없는 자산을 요구할 때만 사용합니다. 익숙한 결과를 얻으려고 다시 뽑지 마세요. 이유와 모든 재추첨을 보고서에 기록합니다.
- 섹션이 실제 콘텐츠와 맞지 않으면 콘텐츠를 억지로 바꾸지 마세요. 가격이 하나인데 요금제 3개 비교가 나오거나 후기가 없는데 인용 5개가 필요한 경우 `--alternatives <role>`로 대안을 보고, 조건이 맞는 것을 `--redraw section:<role>=<id>`로 고릅니다.
- 팔레트는 색뿐 아니라 바탕·잉크·강조·색 면의 비율입니다. 색이 대상의 재료와 충돌하면 한 번 다시 뽑으세요. 대상 고유의 재료·거리·풍경 색이 분명하면 뽑힌 비율을 유지하고 색을 대상에서 가져온 뒤 보고합니다.
- `node <skill>/scripts/draw.mjs --show`로 다시 출력할 수 있습니다. 긴 작업에서는 섹션을 만들기 전에 다시 읽으세요.

### 4. 아이디어 찾기

방향은 구성 방법이고 아이디어는 이 대상만의 페이지로 만드는 장치입니다. 다음 문장의 두 빈칸을 대상 자체에서 채우기 전에는 구현하지 마세요.

> 이 페이지에서는 **[대상에 속한 것]**이 **[선택한 방향이 요구하는 장치]**가 된다.

첫 빈칸은 산출물(시를 인쇄하는 카메라의 종이 쪽지), 물체·단면·실루엣, 사진을 담거나 쌓거나 양끝으로 나눌 이름 글자, 가고 싶은 풍경, 스크롤로 재현할 의식·순서, 표·메뉴·라벨·영수증·초대장·매뉴얼, 다른 업종이 가진 감정에서 찾으세요.

1단계 목록에서 골라야 합니다. **경쟁사 검사:** 가장 가까운 실제 경쟁사의 이름을 넣어도 문장이 성립하면 업종 아이디어에 머문 것입니다. 빵은 모든 빵집의 것이지만 이름의 유래가 된 거리의 일곱 문은 이 빵집만의 것입니다. “깔끔하고 현대적”은 아이디어가 아닙니다.

**살아 있는 요소 하나.** 방문자가 조작하거나 방문마다 달라지는 요소 하나를 아이디어에서 만드세요. 목재를 골라 의자 보기, 이름을 서체로 새기기, 대출액으로 실제 월 납입금 계산하기, 산장의 난로·마지막 배 시간 보기, 방 안에서 크기 비교하기 등입니다. 실제 콘텐츠를 사용하고 휴대전화 엄지로 작동하며 스크립트 없는 대체 수단을 제공해야 합니다. 읽기를 막지 않고 하나의 기능에 집중하세요. 9단계의 장식 모션으로 덧붙이지 말고 6단계에서 페이지 일부로 구현합니다.

**스크롤 장면도 아이디어를 담습니다.** 구현 전에 각 장면이 고유 목록에서 무엇을 보여줄지 정하세요. 스튜디오 자체 타이틀 카드 사이를 통과하고, 실제 운송 경로를 따라가고, 손님이 묵을 방을 전체 화면으로 펼칩니다. 누구에게나 어울리는 이미지로 채우면 화면보호기에 불과합니다.

### 5. 문구 쓰기

마크업 전에 `references/copy.md`에 따라 전체 페이지의 문구 원고를 평문으로 씁니다.

- 모든 제목은 모든 너비에서 **최대 두 줄**입니다. copy.md §2로 먼저 계산하세요. 자신 있는 크기로 약 32자면 안전합니다. 조사한 히어로의 중앙값은 5단어·32자입니다.
- 보조 문장 하나는 제목 바로 아래 32–48px에 함께 보여줍니다. 첫 화면 맨 아래에 붙이거나 애니메이션으로 늦추지 마세요. 제목이 이름·비유라면 이 문장에서 무엇인지 설명합니다. 첫 화면에 실제 버튼으로 주 행동 하나를 두고 행동을 이름으로 씁니다.
- 첫 화면은 방문자의 첫 질문에 큰 글자로 답합니다. 행사는 무엇·언제·어디인지, 제품은 무엇·가격이나 기능, 사람은 누구·하는 일입니다. 행사 날짜는 제목이나 두 번째 크기에 넣으세요. 라인업·메뉴·객실·가격처럼 방문자가 찾는 항목은 각자 제목과 내비게이션 위치를 가집니다.
- 요청한 정보를 빠짐없이 씁니다. 가격 포함 전체 메뉴, 각 객실 상세, 모든 연사·발표, 가격 포함 내역, 실제 질문의 답을 제공합니다. 빈약한 섹션은 깨끗한 페이지가 더 복잡한 페이지에 지는 흔한 이유입니다.
- 브리프의 빈 곳에는 요리·방 이름·요금·프로젝트 제목 같은 예시를 채워 실제 밀도를 보여주되 보고서에 확인 대상으로 적습니다. 고객·인용·리뷰·언론·로고·사업 통계 같은 증거는 지어내지 마세요.

### 6. 정지 상태로 구현하기

애니메이션 없이 완성되어 보이게 만든 뒤 모션을 더하세요. 순서는 다음과 같습니다.

1. **토큰.** 시트의 색·서체 역할을 CSS 사용자 정의 속성으로 만들고 이후에는 토큰만 참조합니다. `assets/base.css`는 리셋·토큰명·유동 서체·그리드·포커스·선택·모션 도우미를 담은 중립적 출발점입니다.
2. **히어로.** 데스크톱과 휴대전화에서 설계 그대로 구현합니다. 다른 부분 전에 큰 것과 작은 것의 크기 차이를 맞추세요.
3. **각 섹션.** 프로젝트의 콘텐츠로 설계의 기하를 유지합니다. 이웃한 섹션의 레이아웃을 반복하지 마세요. 가격·FAQ·푸터까지 아이디어를 이어가세요. 특별한 첫 화면 뒤에 상투적인 블록이 이어지는 것이 흔한 실패입니다.
4. **이미지.** 다음 우선순위를 지킵니다.
   - 프로젝트 자체 자료.
   - 호출 가능한 이미지 도구가 있으면 생성.
   - 대상의 세계를 정직하게 보여주는 공개 컬렉션의 실제 자료. `node <skill>/scripts/assets.mjs "<query>"`로 Openverse, Wikimedia Commons, Art Institute of Chicago, Met을 검색합니다. 기본은 상업 이용 허용 라이선스입니다. 업종보다 고유 목록의 거리·옛 엽서·지도·재료·판화·박물관 물체·식물 도판·별자리를 검색하세요. 크게, 의도를 갖고 사용하며 고르기 전에 각각 봅니다. `--get <ref>`는 `assets/`에 다운로드하고 출처·라이선스를 기록합니다. `--credits`로 푸터 표기를 얻습니다. 자료는 고객 주변 세계를 보여주며 고객의 제품·객실·요리·인물·팀으로 속이지 않습니다.
   - 정직한 사진이 없는 대상의 물건·타일·창문·제품 인터페이스는 팔레트의 실제 색을 사용해 일관된 평면 그래픽으로 코드로 그립니다.
   - 시트에서 뽑힌 사진은 바닷가 집의 바다처럼 일반 사진이 정직하게 맞는 곳에만 사용합니다.
   - 마지막 수단은 서체와 색뿐인 구성입니다.

   자체 제품·공정 영상·사진이 있으면 첫 화면 약 40% 이상으로 크게 보여주세요. 페이지에 “이 사진은 우리 가게가 아님” 같은 제작 설명을 쓰지 마세요. 캡션은 무엇인지 설명하고 작은 출처는 푸터에 둡니다. 가상의 포트폴리오 작업은 제품 그림문자 대신 해당 작업의 타이틀 카드·종료 프레임·포스터를 실제 서체와 세부 요소로 완성해 보여줍니다.

   **검사 기준:** 사진·아카이브·지도·판화·영상·래스터 작품 등 실제 이미지 최소 4개, 보통 6–12개입니다. 소프트웨어의 잘린 인터페이스도 포함됩니다. SVG 그림은 최소 개수에 포함하지 않습니다. 정직한 영상이 있으면 `assets.mjs --video "<query>"`로 찾아 포스터 프레임과 무음 반복 재생을 제공합니다. 자료 찾기가 번거롭다는 이유로 생략하지 마세요. 검색·라이선스·출처·영상·그림·자르기·처리는 `references/imagery.md`를 따릅니다.
5. **살아 있는 요소.** 주장을 증명하는 섹션(보통 히어로·예약)에 4단계 기능을 실제 콘텐츠, 휴대전화 조작, 단순 대체 수단과 함께 구현합니다.
6. **스크롤 장면.** 시트에 있으면 해당 섹션과 함께 지금 만듭니다. `assets/scenes/`의 공통 stage와 장면 파일을 복사하고 프로젝트 사진·문구·토큰으로 채우세요. 장면은 페이지 길이와 각 화면을 결정하는 구도이므로 마지막에 추가하지 않습니다. `references/scenes.md`와 `assets/scenes/demo/<id>.html`을 참고합니다.
7. **충실도.** 데스크톱의 각 화면을 하나의 포스터처럼 봅니다. 지배적인 요소 하나와 필요한 콘텐츠가 있어야 합니다. 빈 바탕이 대부분이면 덜 만든 섹션입니다. 의도적인 휴식은 페이지당 한 번이며 거의 빈 화면이 두 개 이상이면 검사 실패입니다. 본문은 온전한 잉크색, 16px 이상으로 쓰고 회색은 부차적인 주석에만 씁니다.
8. **프레임.** 모든 너비에서 좌우 바깥 여백은 같고 모든 섹션이 페이지 폭을 활용합니다. 왼쪽에 글이 있으면 오른쪽에는 사진·두 번째 열·목록·수치를 둡니다. 비대칭은 그리드 안에서 구현하고 프레임 자체를 비대칭으로 만들지 마세요. 반 화면 이상 완전히 비우지 마세요. 데스크톱 섹션 간격은 120–240px입니다. 방문자가 찾는 섹션마다 제목을, 첫 화면에는 `h1`을 둡니다. 검사기가 이 조건을 측정합니다.
9. **상태와 의미.** 실제 링크·버튼, 보이는 포커스, 대체 텍스트, 독립적으로 구성한 휴대전화 레이아웃을 제공합니다.

판단의 상세 근거가 필요하면 `references/type.md`, `references/colour.md`, `references/layout.md`를 읽으세요.

### 7. 검사 관문

```bash
node <skill>/scripts/lint.mjs <source files or folder>
node <skill>/scripts/inspect.mjs <url or path/to/index.html>
node <skill>/scripts/scenes.mjs <url or path/to/index.html>     # 스크롤 장면이 있을 때
```

`scenes.mjs`는 각 장면의 유지 구간 0, 10 … 100%를 데스크톱·휴대전화·모션 축소 상태로 촬영합니다. 장면이 있으면 `inspect.mjs`도 전체 스크롤을 촬영합니다(`desktop-film-NN.jpg`). 시작하지 않거나 데스크톱에서 정지한 장면은 `FAIL`입니다.

`lint.mjs`는 금지 패턴·상투적인 문구를 검사합니다. `inspect.mjs`는 실제 브라우저에서 1440·768·390px로 열어 제목 줄 수, 글자 크기, 실제 로드한 서체, 색, 선, 그림자, 그라디언트, 대비, 넘침, 여백·한쪽 몰림·빈 구간·제목·이름 없는 섹션·화면 끝의 글자를 측정하고 `.taste-skill/inspect/`에 스크린샷을 저장합니다. 모든 `FAIL`을 수정하고 `WARN`도 디자이너에게 한 문장으로 정당화하지 못하면 문제로 취급합니다. 실패가 없어질 때까지 재실행하되 측정을 속이거나 요소를 숨기지 마세요. 로컬 파일은 임시 로컬 서버에서 제공합니다. 파일 시스템에서 직접 열어야 하는 결과라면 마지막에 `index.html`도 직접 한 번 엽니다.

### 8. 눈으로 보기

검사 통과는 금지 요소가 측정되지 않았다는 뜻일 뿐 좋은 디자인을 보장하지 않습니다. 검사기가 출력한 **모든 너비의 스크린샷**을 이미지 뷰어·Read 도구로 열고 `references/critique.md`의 14개 검토·Awwwards 가중 점수·상한을 적용하세요. 정해진 형식으로 평가를 쓰고 가장 큰 문제 3개를 수정한 뒤 재검사·재확인합니다. 최대 3회입니다.

그림을 보고 판단하세요. 스크린샷에서 보이는 문제는 코드가 어떻든 실제 문제입니다.

### 9. 움직이기

모션 레이어는 필수이며 단일 페이드보다 충분해야 합니다. 검사기는 로드·스크롤 중 실제 움직이는 요소를 세며 8개 미만이면 실패, 16개 미만이면 경고합니다. 6단계에서 만든 스크롤 장면 주변에 다음 네 부분을 더합니다.

1. 시트의 **대표 동작** 하나를 제대로 만듭니다. 뽑힌 장면이 대신할 수 있습니다.
2. 각 섹션 제목→글→사진을 60–90ms 간격, 16–32px 상승과 opacity로 한 번 진입시킵니다. 블록 전체의 페이드 하나로 끝내지 말고 스크립트 실패 시 내용이 숨겨지지 않게 합니다.
3. 버튼·링크·카드·살아 있는 요소의 누름·hover·focus에 피드백을 제공합니다.
4. 찾은 무음 영상 반복, 사진의 느린 확대·이동, 히어로 사진의 스크롤 연동 중 **움직이는 이미지 하나**를 둡니다.

transform과 opacity만 사용합니다. `prefers-reduced-motion`에서는 내용을 유지하고 이동을 없앱니다. 장별 배경색·고정 이야기처럼 전체 화면의 색·레이아웃을 바꾸는 움직임은 구도이므로 6단계에서 만들어 모든 검토 때 확인합니다. `references/motion.md`의 토큰·검증된 조리법을 따르고 다시 검사하여 나타나지 않은 콘텐츠가 없는지 모든 스크린샷을 확인하세요.

장식을 지운 자리는 다른 장식 대신 크기·충분한 내용·대상 고유 이미지·단색 면으로 채우세요. 의도적인 비움은 한 페이지에 최대 한 번입니다.

## 제작 원칙

표시하지 않은 수치는 조사 결과입니다.

**서체**

- 눈에 띄는 크기는 두세 개로 제한하고 큰 것과 작은 것의 차이를 키웁니다. 제목/본문 비 중앙값 4.3. 최상위 최대 글자 크기 중앙값 8.4vw, 약한 사이트 5.0vw.
- 디스플레이 자간 -0.02~-0.05em, 행간 0.85–1.05. 본문 16–20px, 행간 1.45–1.6, 줄 길이 45–75자.
- 전체 크기 단계 최대 5개. 서체 하나가 일반적(조사 사이트 1/3), 최대 두 개.
- 기본 왼쪽 정렬, 가운데 정렬은 최대 한 순간.

**공간**

- 하나의 그리드와 좁은 좌우 여백 16–32px. 큰 요소는 가장자리까지 사용하고 글 블록의 왼쪽 기준선은 전체 2–3개 공유.
- 비대칭은 같은 바깥 여백 안에서 구현하고 치우친 제목 반대편에 요소 배치.
- 섹션 간격은 내부 간격보다 확실히 크게: 데스크톱 120–240px(조사 중앙값 약 240).
- 이웃 섹션은 다른 구도, 카드 격자 금지.

**색**

- 바탕·잉크·강조 하나씩. 강조는 행동과 많아야 다른 요소 하나에 사용.
- 본문은 온전한 잉크색. 옅은 회색 본문을 피함.
- 표면은 선·그림자 대신 작은 명도 차로 구분.
- 섹션 전체 색 면 변경 가능. 그라디언트 전환 없음.

**이미지**

- 작은 이미지 6개보다 큰 이미지 하나. 최고점 사이트의 68%에서 히어로 미디어가 첫 화면 절반 이상 차지.
- 자르기 비·처리를 일관되게 유지. 방향이 달리 지정하지 않으면 직각 모서리(조사 73%).
- 자리표시자·아이콘·추상 도형보다 이미지 없는 편이 낫고, 대상의 색으로 정성껏 그린 그림은 그보다 낫고, 출처를 표시한 실제 세계 사진은 더 좋음.
- 찾은 이미지는 프로젝트에 다운로드하고 페이지·보고서에 출처 명시. 고객 자체 사진으로 제시하지 않음.
- 제목·진술 위에 요소를 겹치지 않음(검사 실패).

**컴포넌트**

- 버튼은 평평한 단색, 모서리는 직각 또는 완전한 원형 중 한 가지로 통일. 상위 사이트 직각 52%, 알약 23%. 9–16px 둥근 모서리는 약한 사이트의 기본값. 좋은 히어로는 버튼이 없거나 하나.
- 내비게이션은 워드마크·평범한 링크 3–5개·행동 하나. 장식 틀 없음.
- 푸터는 사이트맵보다 의도적인 마무리. 좋은 사이트 다수에서 이름이 전체 폭으로 재등장.

## 특수 경우

**기존 브랜드·디자인 시스템:** `--keep palette,type`으로 색·서체를 유지하고 구도만 뽑습니다. 공통 규칙은 유지하되 브랜드 자체가 금지 요소를 요구하면 자산을 보존하고 보고서에 설명한 뒤 해당 규칙만 `--allow <rule>`로 허용합니다.

**기존 페이지·앱 화면의 리디자인·스타일 변경·검토:**

1. 변경 전 프로젝트를 실행하고 `inspect.mjs <url> --out .taste-skill/before`(앱은 `--app`)와 소스 lint를 실행합니다. 프레임워크·스타일 방식(Tailwind v3/v4, CSS modules, styled-components, 일반 CSS), 컴포넌트, 보존할 경로·폼·데이터·동작·브랜드 자산을 읽습니다.
2. **검토 요청은 여기서 멈춥니다.** 변경 전 이미지를 `references/critique.md`로 평가하고 측정값·가장 효과 큰 변경 3개를 보고합니다.
3. 스택·콘텐츠·작동하는 것을 유지합니다. 프레임워크·스타일 라이브러리를 이주하지 말고 의존 파일을 확인한 뒤 추가합니다. 스타일 변경은 레이아웃을 유지하며 뽑힌 서체·색·컴포넌트를 적용합니다. 리디자인은 전체 방향을 뽑아 기존 컴포넌트 안에서 섹션을 다시 구성합니다. 브랜드 고정 요소는 `--keep`하고 실제 콘텐츠로 2단계부터 진행합니다.
4. 효과 대비 위험 순서로 서체→색→프레임(여백·리듬·첫 화면과 섹션 제목)→상태(hover·focus·로딩·빈 화면·오류)→상투적인 컴포넌트 교체를 진행합니다.
5. `.taste-skill/after`로 재검사하고 모든 너비의 전후를 비교하며 기존 링크·폼·메뉴를 모두 조작합니다. 전후 측정값을 나란히 보고합니다.

**컴포넌트·단일 섹션:** 따를 방향이 없을 때만 추첨합니다. 주변 디자인에 맞추고 공통 규칙·제작 원칙을 적용한 뒤 검사합니다.

**결제·폼 백엔드 없음:** 브리프에 실제 목적지가 있으면 연결합니다. 없으면 방문자의 선택과 제목·본문을 채운 `mailto:`를 열거나, 상점은 `#checkout`으로 연결하고 출시 전 연결 필요를 보고합니다. 가짜 결제 폼을 만들지 마세요.

**Chrome·Node 22 없음:** Node 18+의 `lint.mjs`를 실행하고 사용 가능한 브라우저 도구로 촬영·평가합니다. 검사기 실행 불가를 보고합니다.

**네트워크 없음:** `assets.mjs`의 모든 출처에 접근할 수 없으면 그림을 그리고 공개 컬렉션 검색 불가를 보고합니다.
