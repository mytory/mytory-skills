# 생성형 디자인의 흔적 — 시기별 목록

흔적은 페이지를 생성형 결과처럼 보이게 하는 수법입니다. 그 자체로 나쁜 디자인은 아니며 대부분 좋은 사이트의 좋은 아이디어에서 시작했습니다. 이유 없이 어디서나 기본값처럼 쓰이면서 흔적이 됐습니다. 그래서 이 목록은 시기를 밝히며 대체 글꼴·색상·컴포넌트 이름을 제시하지 않습니다. 공개된 “대신 이것을 쓰세요” 목록은 몇 달 만에 다음 흔적이 됐습니다. 여기서 대안은 제품이 아닌 절차(라이브러리에서 추첨, 대상에서 도출)입니다.

`scripts/inspect.mjs`와 `scripts/lint.mjs`가 대부분 탐지합니다. **금지**는 검사 실패, **경고**는 표시되며 이유가 필요하다는 뜻입니다.

6. 문구의 흔적
7. 모션의 흔적
8. 제거만으로 충분하지 않은 이유

| 모든 카드 아래 부드러운 회색 그림자 | 금지 | 명도 차이 또는 박스 제거 |
| 둥근 사각형 아이콘이 위에 붙은 동일한 기능 카드 3개 | 금지 | 제공 섹션 설계 |

| 생성 페이지마다 같은 서체 | 경고(lint: default-font) | 제공 타이포그래피 체계 |

## 3. 세 번째 물결(2025–2026): 해결책이 전형이 되다

앞선 두 물결의 공개 처방은 “따뜻하게, 편집 디자인처럼”이었습니다. 모델이 통째로 받아들여 이제 가장 쉽게 알아보는 생성형 외관이 됐습니다.

| 흔적 | 상태 | 대안 |
| --- | --- | --- |
| 노란 크림 바탕 + 테라코타·녹·점토 강조색 | 조합 금지; 테라코타 단독 금지; 크림 경고 | 제공 팔레트. 저채도 돌색·깊은 글자색·사진·온전한 따뜻한 면에서 따뜻함 얻기 |
| ‘고급스러움’의 지름길로 쓰는 고대비·부드러운 세리프 제목 | 규칙 없음 | 종류에 상관없이 제공 서체 체계 |
| 과도하게 큰 이탤릭 세리프 제목 | 규칙 없음 | 제공된 그대로 |
| 신문 흉내: 가는 선 범벅, 모서리 반경 0, 빽빽한 열 | hairline으로 금지 | 공간과 명도로 구조 형성 |
| “Field notes”, “Quietly trusted by”, “On our desks” 같은 과시적 라벨 | lint: copy | 평범한 섹션 이름 |

## 4. 수상 사이트의 유행이지만 자체 규칙으로 금지

현재 수상 사이트에서 흔한 요소입니다. 연구에서는 하위보다 상위에 더 자주 나타났습니다(패널 관찰: 고정폭 라벨 44% 대 24%, 색인 번호 38% 대 21%; 실측 가는 선 61% 대 52%). 그래도 소유자 결정으로 금지합니다. 생성기가 가장 먼저 복제하며 정보를 전달하지 않고, 이를 쓰지 않는 페이지는 실제 구조를 찾아야 하기 때문입니다.

| 흔적 | 상태 | 대안 |
| --- | --- | --- |
| 작은 고정폭 라벨, ‘기술적’ 목소리로 쓰는 mono, 고정폭 캡션 | 금지 | 본문 서체; 데이터는 고정폭 숫자 |
| 색인 번호: 01 / 02 / 03, (001), “Step 02”, 섹션 번호 | 금지 | 위치·크기·문구로 순서 표현; 실제 목록은 `<ol>` |
| 가는 선: 구분선·줄 그리드·1px 외곽선 박스와 타일 | 금지(박스 3개 이상) | 공간·명도 차이·채운 도형; 막대 자체가 아이디어라면 굵은 막대 |
| 디자인 도구 장식: 십자선·재단선·선택 핸들·점선 가이드·눈금자 | hairline, dashed로 금지 | 제거 |
| 에이전시 메타 장식: 현지 시각·좌표·날씨·버전·“©2026 — Scroll”·가운뎃점 나열 | lint: copy; micro-label | 제거 |
| 화면 곳곳의 작고 자간 넓은 대문자 캡션 | 3개 이상 금지 | 읽을 수 있는 문장식 표기로 설명 대상 옆에 배치 |

이 중 작고 자간 넓은 대문자는 데이터도 지지하지 않습니다. 상위 16%, 하위 57%입니다.

## 5. 구조의 흔적

| 흔적 | 상태 | 대안 |
| --- | --- | --- |
| 큰 제목 크기의 완전한 문장, 3–4줄 | 두 줄 초과 금지 | 약 다섯 단어의 제목; 나머지는 아래 |
| 히어로·로고·기능·추천사·가격·CTA의 상투적 순서 | 규칙 없음; copy.md §1 | 논지의 순서 |
| 모든 섹션이 같은 레이아웃 계열 | critique.md 9번째 검토 | 시트의 다른 구성으로 섹션별 변화 |
| 전부 가운데 정렬 | 72% 초과 경고 | 왼쪽 기준, 가운데 정렬은 한 장면 |
| 모든 요소에 12–16px의 중간 반경 | 없음 | 직각 또는 완전한 원형 중 한 번 결정 |
| 거의 같은 글자 크기 아홉 가지 | 9개 초과 경고 | 차이가 큰 다섯 크기 |
| 지어낸 사회적 증거: 로고·인용·별점·“10,000+ teams” | copy.md §5 | 실제 근거 또는 생략 |
| 이미지 자리의 글자·CSS 박스 | critique.md 상한 | 실제 이미지 또는 이미지 불필요한 설계 |

## 6. 문구의 흔적

`lint.mjs`가 업계식 동사·형용사(unlock, supercharge, seamless, elevate, effortless, cutting-edge, all-in-one …), 교정형 표현(“not just X, it’s Y”), 세 구절 제목, “Get started”·“Learn more” 라벨, 지나치게 많은 em dash, lorem ipsum을 표시합니다. `copy.md` §6을 보세요.

## 7. 모션의 흔적

모든 블록의 똑같은 페이드 상승, 히어로의 수많은 순차 등장, 모든 카드의 호버 상승, 바운스 이징, 의미 없는 무한 반복, 실패해서 빈 영역을 남기는 등장 효과입니다. `motion.md` §9를 보세요.

## 8. 제거만으로 충분하지 않은 이유

흔적을 모두 없애고 아무것도 채우지 않은 페이지는 예의 바른 빈 페이지이며 그것도 흔적입니다. ‘회피 미학’은 누구나 업종과 금지 목록만으로 예상할 수 있습니다. 이 수법들은 아이디어가 있어야 할 빈자리를 채우고 있었습니다. `SKILL.md`의 작업 순서는 그 자리를 먼저 채우기 위한 것입니다. 대상의 아이디어, 제공된 구성, 실제 이미지 또는 과감한 글자 조판을 정하고 나서 검사하세요.
