# 이미지

생성한 페이지는 회색 상자, 사각형 속 아이콘, 가짜 대시보드, 추상적인 덩어리처럼 그림에서 가장 쉽게 빈틈을 드러냅니다. 이 문서는 어떤 이미지를 쓸지, 실제 자료를 어디서 찾을지, 어떻게 자르고 배치할지, 자료가 없으면 어떻게 할지 설명합니다.

## 1. 조사에서 측정한 내용

- 조사 사이트의 60%는 미디어 하나가 첫 화면의 절반 이상을, 그중 절반은 거의 전체를 차지합니다. 상위 사이트는 각각 68%, 56%, 낮은 사이트는 48%, 39%입니다.
- 히어로에 미디어가 전혀 없는 경우는 15%뿐이며 의도적으로 타이포그래피를 내세웁니다.
- 73%는 미디어 모서리가 직각입니다. 둥근 경우 보통 반지름은 약 12px로 모든 이미지에 같습니다.
- 상위 페이지의 이미지 수 중앙값은 37개, 낮은 페이지는 5개입니다. 강한 사이트는 보여 주고 약한 사이트는 말로 설명합니다.
- 평가단 분류: 종류 혼합 32%, 사진 14%, 생성형/WebGL 장면 13%, 실제 제품 인터페이스 12%, 3D 렌더 11%, 일러스트 9%, 동영상 6%, 글자만 3%입니다.
- 6.8점 미만인 54개 사이트 중 13개는 복잡한 이미지 위에서 글자가 묻히거나 대비가 부족해 가독성을 약점으로 지적받았습니다.
- 2026년 10월 Awwwards 오늘의 사이트 91개 조사(12절)의 이미지 수 중앙값은 7개(상위 8개, 최하위 2개), 영상 사용률은 42%(상위 절반, 최하위 16개 중 1개)입니다.
- 스크롤 화면의 42%는 이미지가 없고 19%는 이미지 면적이 90% 이상입니다.
- 이미지의 94%는 직각 모서리이며, 보통 두 가지 비율이 전체의 4분의 3을 차지합니다.

## 2. 사용할 이미지 결정

다음 순서로 고릅니다.

1. **프로젝트 자체 이미지.** 제품, 장소, 사람, 작업물 사진입니다. 실제 대상의 평범한 사진도 다른 대상의 아름다운 사진보다 낫습니다. 무엇이 있는지 묻고 저장소를 살핍니다.
2. **이 세션의 이미지 도구로 생성할 이미지.** 사진가에게 주듯 대상, 각도, 빛, 배경, 자르기 비율, “텍스트 없음”을 명시합니다. 히어로부터 생성하고 나머지 빛을 맞춥니다.
3. **공개 컬렉션에서 찾은 대상 세계의 실제 이미지**(3절). 기록관·박물관·사진가의 공개 자료에는 출처를 밝히고 쓸 수 있는 사진이 수백만 장 있습니다. 고객의 도시와 거리의 옛 엽서, 동네 지도, 재료, 업종 판화, 관련 박물관 소장품을 찾습니다. 오해를 만들지 않는 실제 자료는 같은 대상을 그린 그림보다 세부 묘사와 역사를 풍부하게 담습니다. 고객 자신의 제품·방·요리·인물·팀 사진으로 보일 수 없어야 합니다.
4. **대상 자체를 코드로 그린 이미지**(8절). 오해 없이 쓸 실제 사진이 없다면 제품의 형태, 장소의 타일과 창, 거리 지도, 도구의 출력 문서, 소프트웨어 인터페이스를 그립니다. 실험에서는 대상을 정성껏 그린 페이지가 무관한 사진을 빌린 페이지와 아무것도 보여 주지 않은 페이지보다 항상 나았습니다.
5. **방향 시트에 배정된 사진.** 장소·빛·질감·날씨의 실제 사진입니다. 바닷가 집에 바다, 조용한 휴양지에 안개처럼 일반적인 사진이어도 정직한 경우에만 씁니다. 특정 제품·요리·방·사람·화면을 대신하면 안 됩니다. 식당의 안개 낀 고속도로 사진은 즉시 스톡 사진처럼 보이며 평가단도 알아챕니다.
6. **글자와 색만 사용**(9절). 의도적으로 선택합니다.

`draw.mjs`의 `--have`에는 실제 보유 자료만 알립니다. 제품 사진도 이미지 도구도 없으면 `product-photo`를 넘기지 않아야 물건을 보여 줘야 하는 방향을 피합니다. 공개 컬렉션 자료는 프로젝트 자체 사진이 아니므로 `photography`로 넘기지 않습니다.

## 3. 공개 컬렉션에서 실제 이미지 찾기

`scripts/assets.mjs`는 키 없이 네 공개 출처를 검색하고 직접 이미지 URL, 원문 페이지, 크기, 창작자, 라이선스, 출처 문구를 출력합니다.

- **Openverse:** Flickr, Wikimedia Commons, 박물관, 도서관을 통합 검색합니다.
- **Wikimedia Commons:** 기록 사진, 옛 지도, 판화·책 스캔, 현재 장소 사진입니다.
- **시카고 미술관과 메트로폴리탄 미술관:** 퍼블릭 도메인 회화·판화·소묘·사진·직물·사물의 고해상도 스캔입니다.

```bash
node <skill>/scripts/assets.mjs "ghent postcard"
node <skill>/scripts/assets.mjs "fig" --source museums --orientation portrait
node <skill>/scripts/assets.mjs "basalt texture" --min-width 2400 --source openverse,commons
node <skill>/scripts/assets.mjs --get commons:36649959,met:707892     # download, record the credits
node <skill>/scripts/assets.mjs --credits                             # footer line and report list
```

기본값은 상업 이용 가능한 CC0, 퍼블릭 도메인, CC BY, CC BY-SA와 폭 1000픽셀 이상만 남기고 출력하는 이미지가 실제로 열리는지도 확인합니다. `--license pd`는 출처 표기가 필요 없는 자료만 남깁니다. `--orientation`, `--min-width`, `--limit`로 좁히고 `--source`로 출처를 고르며 `--json`으로 원시 결과를 받습니다. 결과의 참조값(`commons:36649959`)을 `--get`에 넘깁니다.

**검색 대상.** 업종명보다 목록(SKILL.md 1단계)의 구체적인 대상을 검색합니다. “bakery”는 다른 사람의 빵집을 찾습니다.

- **장소:** 도시, 거리, 항구, 계곡의 옛 엽서·사진(“ghent postcard”, “rotterdam harbour 1920”)과 현재 모습(“gent korenmarkt”).
- **지도:** 거리 배치, 만의 해도, 계곡 지질(“ghent old map”, “nautical chart lisbon”).
- **재료:** 부두의 돌, 참나무 결, 유약, 타일처럼 표면으로 읽힐 만큼 가까운 사진(“azulejo tiles”, “basalt cobblestones”, “oak grain”).
- **업종의 역사:** 옛 도구, 판화·상품목록의 공예, 특허 도면(“bread oven engraving”, “potter's wheel”, “bicycle patent drawing”).
- **비슷한 박물관 소장품:** `--source museums`를 사용합니다. 커피 세트 공방에는 1810년경 커피 세트, 서핑 학교에는 파도 목판화, 무화과 과수원에는 무화과가 그려진 도자 접시 등을 찾습니다.
- **과학 이미지:** 동식물 도판(“botanical engraving fig”), 성도, 현미경 사진, 해안 위성사진, 지질 단면도입니다.

장소 고유의 단어(“blue tile”보다 azulejo, “market square”보다 Korenmarkt)를 쓰고 매체(postcard, engraving, old map, lithograph, aerial photograph)나 연대를 더해 아이디어마다 두세 번 검색합니다. 박물관은 “fig”, “harbour”, “teapot”처럼 한두 단어가 잘 맞습니다.

**좋은 검색 결과의 조건.**

- 대상의 세계에 속하며 가까운 경쟁사의 페이지에는 맞지 않습니다.
- 필요한 비율로 잘라도 읽힙니다. 결정 전에 `--get`으로 내려받아 직접 엽니다. 제목은 그림을 대신하지 못합니다.
- 충분히 큽니다. 화면을 가득 채울 때는 표시 폭의 두 배가 필요합니다. 스크립트는 최대 크기를 출력합니다. 1024픽셀 Flickr 사진은 최대 반폭 용도입니다.
- 한 페이지의 다른 이미지와 한 계열입니다. 모두 판화, 같은 시대 사진, 같은 빛의 표면 사진처럼 맞춥니다. 1900년 엽서·현대 스톡 사진·식물 도판의 혼합은 스크랩북 같습니다.
- 워터마크·박힌 텍스트·로고·잘라낼 수 없는 프레임이나 스캐너 가장자리, 고객의 직원·손님으로 오인할 생존 인물이 없어야 합니다.

**창의적으로 사용하기.** 찾은 이미지는 장식이 아니라 재료입니다.

- **기록 사진 한 장을 전면 히어로로:** 오늘의 상호 뒤에 100년 전 거리 사진을 놓고 연도를 캡션에 씁니다.
- **박물관 판화를 선이 질감이 될 때까지 확대:** 촘촘히 자른 하나의 모티프를 여러 크기로 반복합니다. 히어로의 무화과 도판 전체, 메뉴 옆의 잎 하나처럼 씁니다.
- **흰 종이의 판화·지도에 `mix-blend-mode: multiply`:** 페이지 색 바탕에 잉크가 직접 놓인 듯 만듭니다(6절).
- **실제 거리 지도를 연락처 절로:** 문 위치를 표시하고 원본의 북쪽·축척을 사용합니다.
- **재료 확대 사진을 전체 면으로:** 영업시간 뒤 부두의 돌을 놓습니다.
- **옛 엽서·도판 연작을 갤러리로:** 크기와 처리를 통일합니다.

처리는 6절 범위, 즉 원본 그대로, 전체 흑백, 바탕 위 multiply만 사용합니다.

**정직하게 사용하기.**

- **찾은 사진은 고객 자체 사진이 아닙니다.** 도시·재료·역사·제품의 종류를 보여 줄 수 있지만 고객 제품·방·요리·사람·팀·손님을 대신하면 안 됩니다. 빵집 카운터·파스타 접시·웃는 바리스타·객실을 고객 것으로 오인할 수 있으면 쓰지 않습니다.
- **필요한 캡션은 원문에 근거:** 기록관 설명의 대상·시점(“Gand, unloading a steamer, 1905”)을 씁니다. 고객과 연결하는 설명을 지어내지 않습니다.
- **모든 사진을 기록하고 출처 표기:** `--get`은 출처·창작자·라이선스·페이지를 `assets/credits.json`에 기록합니다. CC BY/CC BY-SA는 제목·창작자·원문 링크·라이선스 링크가 필요합니다. `--credits`가 푸터용 HTML 한 줄을 출력합니다(10절). 퍼블릭 도메인도 가능하면 표기합니다.
- **라이선스 준수:** CC BY-SA의 변형본(재색칠·다른 이미지와 합성)은 같은 라이선스로 공유해야 합니다. 비상업(NC)·변경금지(ND)는 고객 사이트에 부적합해 요청 없이는 제외합니다. `note`를 읽습니다. 인격권·상표권, 미국에서만 퍼블릭 도메인인 자료, 라이선스 대신 기록관 선언이 붙은 자료도 있습니다.
- **핫링크 대신 내려받기:** `--get`은 `assets/`에 폭 1920픽셀로 저장합니다. 반폭은 `--width 1280`, 큰 히어로는 원본이 허용하면 `--width 3840`을 씁니다. 오프라인에서도 작동하고 원본 이동으로 깨지지 않으며 외부 서버를 호출하지 않습니다. 기본 허용 라이선스는 모두 복제를 허용합니다.
- **보고서에 목록:** 파일·제목·창작자·라이선스·원문 페이지·출처 표시 위치를 적습니다. `--credits`도 출력합니다.

아이디어마다 정직한 검색을 두세 번 해도 맞는 자료가 없으면 그립니다(8절). 대상을 위해 그린 그림이 그저 비슷한 사진보다 낫습니다. 네트워크가 없어 모든 출처에 연결할 수 없으면 그림을 그리고 보고서에 이유를 씁니다. 영상도 같은 스크립트의 `--video`로 찾습니다(11절).

## 4. 방향 시트에 배정된 사진

- 같은 대상·빛을 공유하는 한 세트에서 8장을 제시합니다. 3~6장을 사용합니다.
- 각 줄은 여백이 조용한 영역을 알려 줍니다. 거기에 글자를 놓거나 이미지 밖에 둡니다.
- 추가 사진: `node scripts/draw.mjs --photos list`, `--photos <set>`, 설명 검색은 `--photos "fog coast"`.
- URL은 `https://picsum.photos/id/<id>/<width>/<height>`입니다. CSS 표시 크기의 두 배 픽셀을 요청하되 폭 약 2400을 상한으로 합니다. 흑백은 `?grayscale`을 붙입니다.
- Unsplash 사진을 Lorem Picsum이 Unsplash 라이선스로 제공합니다. 사용 id를 보고서에 적으며, 프로젝트 자체 사진으로 교체할 용도입니다.

## 5. 자르기와 배치

- **소수 비율을 정해 유지:** 인물 4:5, 풍경 16:10, 디테일 1:1 등. 무작위 비율은 스톡 사진 모음처럼 보입니다.
- **크게 사용:** 전폭 또는 반폭·전체 높이는 존재감이 있습니다. 작은 사진 6장 그리드는 그렇지 않습니다. 좋은 사진에는 공간을 주고 나쁘면 뺍니다.
- **의도해서 자르기:** `object-fit: cover`와 이미지별 `object-position`으로 중앙 밖·삼분선·텍스트 쪽 등 구도에 맞게 대상을 놓습니다.
- **가장자리에 닿게:** 전면 또는 한쪽으로 넘기면 설계한 느낌입니다. 사방 동일 여백은 기본 배치처럼 보입니다.
- **겹침은 드물고 의도적으로:** 제목 마지막 줄이 이미지 윗변에 걸치거나 작은 이미지가 큰 이미지에 40–80px 겹치도록 합니다. 화면당 최대 한 번입니다.
- **직각 모서리:** 방향이나 단일 모티프 형태가 요구할 때만 바꿉니다. 둥글면 모든 이미지에 같은 반지름을 씁니다.
- **프레임 없음:** 테두리·그림자·기기 목업·브라우저 테두리를 두르지 않습니다.
- **캡션:** 이미지 아래 작은 크기·부드러운 잉크색의 짧은 한 줄을 왼쪽 가장자리에 맞춥니다. 대부분은 필요 없습니다.
- 위치·크기·휴대폰 대응은 12절을 봅니다.

## 6. 이미지 처리

페이지 전체에 하나의 처리를 적용합니다.

- **원본 그대로:** 기본입니다. 빛이 이미 맞는 사진을 고릅니다.
- **흑백:** `filter: grayscale(1) contrast(1.05)` 또는 URL의 `?grayscale`. 혼합 세트를 통일하며 편집·타이포그래피 방향에 맞습니다. 모든 이미지에 적용하거나 전혀 적용하지 않습니다.
- **바탕 위 multiply:** 밝은 단색 바탕의 `mix-blend-mode: multiply`는 스튜디오의 흰 배경을 없애 제품이 색 위에 직접 놓인 듯 만듭니다.
- **어두운 페이지에 맞춰 어둡게:** `filter: brightness(0.85) contrast(1.05)`로 가장자리를 바탕에 스며들게 합니다.

사진 위 색 씌우기, 듀오톤 오버레이, 블러, 노이즈 레이어, 비네트, 기울인 폴라로이드 그림자 프레임은 허용 처리에 포함하지 않습니다.

사진 위 글자에는 텍스트 영역에만 중성 차광막을 둡니다. 검정 40–55% 단색 블록 또는 아래쪽 3분의 1에 검정 55%에서 투명으로 사라지는 그라디언트입니다. 유색 오버레이는 쓰지 않습니다.

## 7. 소프트웨어 보여 주기

- 축소 스크린샷·장식 목업 대신 신뢰할 내용의 실제 인터페이스 조각을 HTML로 원래 크기에 만듭니다. 제어 하나·행 하나·패널 하나처럼 요지를 보여 주는 부분만 자릅니다.
- 실제 라벨, 합계가 맞는 숫자, 호버·선택 항목 하나, 정확한 정렬을 갖춥니다. 글자 대신 회색 막대를 쓰는 것은 그림이 없는 것보다 못합니다.
- 페이지에 직접 또는 단색 무대 위에 놓습니다. 노트북 프레임은 쓰지 않습니다. 휴대폰 앱일 때만 단순한 둥근 사각형 프레임을 허용합니다.
- 조각 안에서는 제품 자체 UI 관례(작은 반지름·1px 테두리·열린 메뉴 그림자)를 따릅니다. 루트에 `data-ui`를 두면 검사기·린터가 내부를 제외하고 주위 페이지에는 공통 규칙을 적용합니다. 잘라낸 조각에만 쓰며 제목·절 전체를 감싸면 실패합니다. CSS는 `[data-ui] .row { … }`처럼 `[data-ui]` 아래 작성해 페이지 스타일과 구분합니다.
- 실제 스크린샷을 제공받으면 최소 한 번은 자르지 않고 크게 보여 줍니다.

## 8. 대상을 직접 그리기

촬영할 실제 대상도 공개 컬렉션의 정직한 자료도 없으면 잘 그립니다. 인라인 SVG와 CSS로 충분합니다. 찾은 사진은 고객 주변 세계를, 그림은 고객 자체 대상을 보여 주며 함께 쓸 수 있습니다.

- **대상 자체를 그리기:** 의자의 세 다리와 좌판 나뭇결, 빵집 문 위 에나멜 간판, 오두막 창 두 개와 난로 연통, 거리 지도, 도구의 청구서, 축제 무대 등입니다. 무엇을 묘사하는지 대상의 세계에서 이름 붙일 수 없다면 장식입니다.
- **페이지 전체에 하나의 시각 언어:** 면으로 채우고 윤곽선은 없애거나 한 굵기로 통일하며 모서리·곡선 어휘를 맞춥니다. 회색 대신 팔레트의 실제 바탕·강조색을 온전히 씁니다. 한 세트로 보이면 정체성이 생기고 섞이면 클립아트 같습니다.
- **색이 재료:** 마감이 중요한 제품은 그 마감 색으로, 바닷가 집은 바다의 파랑과 모래색으로 그립니다. 회색 자리표시자 페이지를 만들지 않습니다.
- **세 단계 디테일:** 평가단은 단순한 그림을 항상 기초적이라고 불렀습니다. 한눈에 읽히는 큰 형태, 손잡이·창틀·계단 같은 중간 형태, 제작자 표시·번지·깨진 타일·경첩·지붕의 새 같은 작은 디테일을 둡니다. 빛은 그라디언트 대신 각 부피의 밝은 면·그늘 면 같은 평평한 명도 단계로 만듭니다. 전체 크기에서 자리표시 아이콘으로 보이면 미완성입니다.
- **크게 그려 역할 부여:** 히어로의 주 요소, 전폭 띠, 타일 세트, 푸터 표식으로 씁니다. 작은 낙서를 흩뿌리면 채우기처럼 보입니다.
- **아이디어를 이어 가기:** 같은 물건을 여러 크기로 반복하고 타일 격자를 영업시간, 지도를 예약 절로 활용합니다.
- **정직성:** 실제 제품 사진으로 오인할 수 있으면 첫 그림 옆 또는 푸터에 사진 확보 전 그린 이미지임을 작은 글자로 밝힙니다. 보고서에는 사진 대용 그림을 나열합니다.
- **피할 것:** 그라디언트로 입체감을 낸 덩어리, 등각 클립아트, 노트북 앞 사람의 일반 선화, 떠다니는 추상 형태, 사각형 속 아이콘은 생성형 디자인처럼 보입니다.

## 9. 글자와 색만 사용하기

숨겨야 할 빈틈이 아니라 정당한 선택입니다. 조사에서 이미지 없는 7개 사이트의 평가 중앙값은 7.5로 전체 7.2보다 높았습니다.

- 글자를 이미지로: 문장 하나 10–14vw, 목록 5vw, 숫자는 대형 글자로 만듭니다.
- 색을 크게: 전체 면, 반전 절, 두 색 분할을 씁니다.
- 방향에 맞으면 대상의 고유한 원·호·홈 하나를 평면 모티프로 CSS로 그리고 뷰포트로 자릅니다.
- 사각형 속 아이콘·추상 그라디언트·점 격자·물결 구분선·떠다니는 형태·이모지·일반 선화·그림을 넣을 빈 상자를 추가하지 않습니다.

## 10. 마크업과 출처 표기

`--get`으로 프로젝트에 내려받은 이미지를 히어로로 사용합니다.

```html
<img src="assets/fig-engraving.jpg" width="1920" height="2807" fetchpriority="high" decoding="async"
     alt="Hand-coloured engraving of a fig cut open, with its flowers and seeds, in black, pink and green">
```

아래쪽에 배정된 사진을 사용합니다.

```html
<img src="https://picsum.photos/id/626/2400/1500" width="2400" height="1500"
     alt="Red and white lighthouse in a turquoise sea below a chalk cliff" loading="lazy" decoding="async">
```

`--credits`가 출력한 출처를 푸터에 둡니다.

```html
<p class="credits">Pictures: <a href="https://commons.wikimedia.org/wiki/File:Fig_(Ficus_carica_L.);_57_segments_of_flowers_and_fruits_at_Wellcome_V0043000.jpg">“Fig (Ficus carica L.): 57 segments of flowers and fruits”</a>, <a href="https://creativecommons.org/publicdomain/mark/1.0/">public domain</a>, via Wikimedia Commons.</p>
```

- `width`와 `height` 또는 CSS의 `aspect-ratio`로 로딩 중 이동을 막습니다.
- 히어로는 `fetchpriority="high"`, 나머지는 `loading="lazy"`입니다.
- `alt`는 그림 내용을 쉬운 말로 설명하고 반복 장식은 `alt=""`로 둡니다. 스크립트 제안값은 기록관 제목이므로 실제 보이는 내용으로 고칩니다.
- 컨테이너에 바탕·표면 톤의 `background-color`를 지정해 이미지가 오기 전에도 구성이 완전하게 보이게 합니다.
- 출처 문구는 푸터 디자인의 일부로 충분한 대비와 링크를 갖춥니다. 본문 크기를 쓰며 본문이 많은 페이지에서만 한 단계 줄입니다. 긴 출처가 작은 글자로 페이지에서 가장 흔한 크기가 되면 검사기의 본문 크기 검사에 걸릴 수 있습니다. 모든 사진을 한 줄에 표기하고 사진 위에 출처 캡션을 얹지 않습니다. 현재 사용하는 사진만 표기합니다.
- 깨진 이미지는 검사 실패입니다. 스크린샷에서 모든 이미지를 확인합니다.

## 11. 동영상

거리 끝의 강, 회전하는 로스터 드럼, 올라가는 목조 골조처럼 대상 세계의 움직이는 그림도 사진처럼 절을 이끌 수 있습니다. `assets.mjs --video`는 키 없이 Wikimedia Commons(모든 영상에 웹 크기 변환본 제공, 짧은 클립에 가장 적합), Internet Archive의 Prelinger Archives(1920~1970년대 산업·교육·도시·가정 영상, 대부분 퍼블릭 도메인이며 김), NASA(궤도에서 본 지구·발사·항공기·실험실)를 검색합니다. 누구나 업로드하고 라이선스를 검증하지 않는 Internet Archive의 나머지 자료는 제외합니다.

```bash
node <skill>/scripts/assets.mjs "coffee roasting" --video
node <skill>/scripts/assets.mjs "river" --video --source commons,nasa --orientation landscape
node <skill>/scripts/assets.mjs --get commons:49769620        # the clip, a poster frame, the credit
```

720p 이하 변환본을 고르며 `--res`로 바꿉니다. 짧은 클립부터 길이·크기를 출력하고 25MB 초과 또는 1분 초과에 표시합니다. `--get`은 `--max-mb` 없이는 25MB 초과를 거절하며 Commons·NASA의 정지 프레임을 포스터로 저장합니다. Archive 정지 이미지는 너무 작습니다. 10분 기록 영화는 그대로 쓰기 무거우므로 설치된 ffmpeg로 몇 초를 잘라 쓰거나 짧은 영상을 고릅니다. 라이선스·출처·정직성은 사진과 같습니다(3절).

**클립 선택.**

- **짧게:** 물·연기·회전 드럼·교통·나뭇잎·먼 군중처럼 5~20초이며 반복 경계가 튀지 않아야 합니다. 끝까지 보고 고릅니다.
- **가볍게:** 일반 절 약 5MB 미만, 히어로 10MB 미만입니다. 조사 원본은 주로 1920×1080 또는 1280×720, 길이 중앙값 10초입니다. 글자 뒤에는 720p로 충분합니다. 전면 히어로는 휴대폰용 세로 720×1280을 자르거나 대상에 `object-position`을 맞춥니다.
- **깨끗하게:** 슬레이트·타이틀·로고·워터마크·박힌 캡션이 없어야 합니다. NASA·기록 영상은 슬레이트로 시작하기 쉬우며 포스터도 그 장면일 수 있습니다. 고객 직원·손님으로 오인할 인물도 없어야 합니다.
- **고객 자체 영상으로 오인 금지:** 찾은 로스터리 영상은 이 로스터리의 영상이 아닙니다.
- **찾은 영상은 페이지당 하나, 최대 둘:** 고객 주변 세계를 보여 주는 데 쓰며 셋이면 주제가 되어 버립니다. 자체 영상은 더 쓸 수 있습니다. 조사상 영상 사용 사이트의 중앙값은 3~4개입니다. 어느 경우든 **화면당 움직이는 그림 하나**입니다. 나란히 도는 두 루프는 소음입니다.

**페이지에 배치.**

- `--get` 출력대로 음소거·반복·인라인·포스터·고정 크기를 적용합니다: `<video autoplay muted loop playsinline preload="metadata" poster="assets/river-poster.jpg" width="854" height="480" aria-hidden="true"><source src="assets/river.webm" type="video/webm"></video>`. 장식 루프는 소리·제어 UI가 없습니다. `aria-hidden`인 장식이므로 중요한 정보는 옆 글에 담습니다.
- 포스터는 재생 전·느린 연결·동작 줄이기에서 표시되므로 한 장으로도 성립해야 합니다. 슬레이트나 흐림이면 직접 프레임을 추출하거나 찾은 사진을 씁니다.
- 조사에서는 포스터가 31%뿐이라 재생 전 빈 회색 상자가 결점으로 기록됐습니다. 여기서는 모든 클립에 필요합니다.
- 화면에 보일 때만 재생하고 `prefers-reduced-motion: reduce`에서는 포스터만 보여 줍니다.

  ```html
  <script>
    const calm = matchMedia('(prefers-reduced-motion: reduce)');
    const clips = [...document.querySelectorAll('video[autoplay]')];
    const inView = new Set();
    const sync = (v) => {
      if (calm.matches) return;
      if (inView.has(v)) v.play().catch(() => {}); else v.pause();
    };
    const settle = () => {
      for (const v of clips) {
        if (calm.matches) { v.removeAttribute('autoplay'); v.pause(); v.load(); }
        else if (inView.has(v)) v.play().catch(() => {});
      }
    };
    const watch = new IntersectionObserver((entries) => {
      for (const e of entries) {
        if (e.isIntersecting) inView.add(e.target); else inView.delete(e.target);
        sync(e.target);
      }
    }, { threshold: 0.2 });
    clips.forEach((v) => watch.observe(v));
    settle();
    calm.addEventListener('change', settle);
  </script>
  ```

- 사진처럼 자르고 배치합니다(5·6절). `object-fit: cover`, 단일 비율, 직각 모서리, 프레임 없음, 로딩 중 바탕색을 씁니다.
- 본문 뒤에는 놓지 않습니다. 최대 제목·한 줄·동작 하나만 얹고 포스터뿐 아니라 전체 루프에서 그 위치의 대비를 확인합니다. 한 프레임이라도 4.5:1(24px 이상은 3:1) 아래면 6절 차광막을 쓰거나 글자를 영상 밖으로 옮깁니다. 제목·주장 위를 다른 요소로 가리지 않습니다.
- 동작이므로 페이지의 유일한 움직임으로 삼거나 다른 것이 움직이지 않는 절에 둡니다.
- 사진과 함께 출처를 표기합니다. `--credits`는 “Pictures and footage:” 푸터 한 줄과 클립 길이가 포함된 보고서 목록을 출력합니다.
- 히어로 배경·인라인 루프·커지는 프레임·구석 카드의 위치와 측정값은 12절을 봅니다. 중요한 재생을 호버에만 의존하지 않고 소리 있는 전체 영상은 재생 버튼으로 제어 가능한 플레이어를 엽니다.

## 12. 이미지와 영상의 자리

최근 Awwwards 오늘의 사이트 100개(2026년 7월 10일~10월 17일, 1440×900·390×844 촬영) 중 사용할 수 있었던 91개에서 좋은 페이지의 이미지 배치를 측정했습니다. 평가단이 각 사진 위치를 기술하고 Awwwards 방식으로 채점했으며 스크립트가 화면당 이미지 면적을 측정했습니다. 상위는 7.5점 이상 36개, 최하위는 7.3점 미만 16개입니다. 점수 범위가 6.7~7.9로 좁고 한 점수에 약 0.5점의 오차가 있으므로 배치와 점수의 관계를 법칙보다 경향으로 읽습니다.

### 화면에서 이미지가 차지하는 면적

- **전부 또는 없음:** 사진·영상·배경 이미지(캔버스 제외)를 합친 스크롤 화면 중앙값은 16%지만 그 근처는 드뭅니다. 42%는 이미지가 없고 19%는 90% 이상이며 20~60%인 화면은 19%뿐입니다. 이미지는 화면을 이끌거나 비켜납니다.
- **약 3분의 1과 휴식:** 본문에 이미지를 둔 67개 사이트의 평균 화면은 이미지 36%(중간 50% 범위 18~69%)입니다. 상위는 30%이며 화면의 28%는 이미지가 전혀 없습니다. 글자 화면이 이미지 화면 사이의 휴식입니다.
- **첫 화면:** 41%는 이미지가 절반 이상, 32%는 거의 전부입니다. 29%는 전면 사진·영상이 첫 화면 전체이며 약 4분의 1은 영상이 히어로 주 이미지입니다.
- **장면은 이미지와 다름:** 91개 중 66개는 WebGL 캔버스가 화면의 30% 이상을 덮어 캔버스까지 세면 중앙값이 전면입니다. 최하위에는 캔버스가 전부인 경우가 많습니다. 사용 가능한 최하위 5개(6.7~7.0점)는 모두 캔버스로 그리고 본문 이미지는 최대 2개입니다.
- **텍스트 면적은 작음:** 화면 중앙값은 8%입니다. 글자는 이미지 옆에 빽빽하게 채우기보다 크고 성기게 놓습니다.
- **중앙에서 벗어남:** 절별 집계에서 좌·우 배치 939회, 중앙 273회, 전면·글자 뒤 269회입니다.
- **휴대폰에는 더 많은 이미지:** 화면 중앙값은 19%, 첫 화면은 27%로 데스크톱 17%보다 높습니다. 전면 이미지는 세로로 잘라 화면을 채우고 분할은 이미지를 전폭으로 먼저 놓습니다.

### 개수

- **페이지당 중앙값 7장:** 중간 50%는 1~25장, 상위 8장(4~27), 최하위 2장(0~4)입니다. SKILL.md 6단계의 최소 4장·보통 6~12장은 조사 상위 절반에 해당합니다.

### 배치별 사용법

각 항목은 사용 시점, 1440×900에서의 크기와 위치, 휴대폰 대응, 실패 조건입니다.

**반폭·3분의 2 분할**

- *사용:* 주장과 증거 사진을 함께 놓습니다. 좋은 페이지에서 글자와 사진을 짝짓는 가장 흔한 방식입니다.
- *배치:* 사진 폭 중앙값 42%(중간 50% 33~49%), 최대 3분의 2이며 절 전체 높이를 씁니다. 680×850·720×900이 대표적입니다. 38%는 세로이며 주로 4:5·3:4입니다. 글자는 50%선(x=720) 또는 사진 끝선에서 시작해 위나 아래에 맞추고 반쪽 중앙에는 두지 않습니다. 사진 바깥 변을 뷰포트에 붙입니다. 조사에서는 약 30%만 그렇게 했고 사방 여백은 기본 배치처럼 보입니다(5절). 좌우 교대는 3행 이상에서만 합니다.
- *휴대폰:* 이미지 먼저 전폭(세로 4:5, 가로 4:3), 글자는 아래입니다.
- *실패:* 세 절 연속 같은 분할, 반쪽 중앙에 뜬 사진, 약 30자보다 좁은 텍스트 열입니다.

**전면 띠**

- *사용:* 글자 화면 사이 한 화면을 장소·작업물·실물 크기 사물의 사진 하나가 이끕니다. 3~4화면마다 최대 한 번입니다.
- *배치:* 폭 100%, 높이 1~1.5화면(1440×900 기준 중앙값 900px, 중간 50% 890~1170px, 비율 1.4~1.9)입니다. 느린 패럴랙스는 프레임보다 4~10%(조사상 변마다 32~72px)만 크게 만들고 그 범위 안에서 움직입니다. 글자는 제목·한 줄 또는 없으며 조용한 이미지 영역의 구석에서 32~64px 안쪽에 둡니다.
- *휴대폰:* 대상을 `object-position`에 맞춘 전면 세로 자르기, 글자는 아래쪽 4분의 1입니다.
- *실패:* 밝은 영역 위 11~14px 흰 글자, 사이 내용 없는 세 띠, 단순 장식 띠입니다.

**사진 고정·텍스트 스크롤**

- *사용:* 한 사진과 연결된 목록·단계·긴 문단입니다. 항목마다 사진이 바뀌면 아래 미리보기 목록을 씁니다.
- *배치:* 2~6화면 길이 절 안에 100vh sticky 무대를 둡니다. 조사상 스크롤 구간은 보통 1800~5400px입니다. 사진은 절반(대표 세로 685×880), 3분의 2 또는 전체를 차지하고 글자가 단색 패널 위로 지나갑니다. 텍스트 행 간격은 약 150px로 2~3행이 보입니다.
- *휴대폰:* 고정을 풀어 이미지 먼저·글자 아래로 둡니다. 항목별 사진 교체라면 화면 상단 40%의 띠로 유지합니다.
- *실패:* 글자가 사라진 뒤 사진만 남는 긴 구간(평가단은 휴대폰의 빈 무대를 여러 번 기록), 고정 사진 위 본문입니다.

**확대되는 안쪽 프레임**

- *휴대폰:* 16px 여백 안 전폭에서 전면 세로로 키우거나 확대를 생략합니다.
- *실패:* 세 번 스크롤 동안 확대만 보임, 첫 프레임의 로딩 표시·빈 상자(포스터를 주고 진입 전 로드), 두 번 사용입니다.

**불균등 모자이크**

- *사용:* 작업 모음 또는 한 장소의 여러 모습으로 5~12장입니다.
- *배치:* 2열 또는 24열 격자의 3개짜리 행입니다. 폭 2~3종(32%·48%·65%, 또는 5·7·12열), 이웃 세로 어긋남 120~190px, 행 사이 130~450px, 비율 1~2종과 각 사진 아래 캡션을 씁니다.
- *휴대폰:* 전폭과 약 70%폭을 번갈아 쓰는 1열 또는 어긋남을 유지한 120~180px 타일 2열입니다.
- *실패:* 무작위 비율·어긋남은 스톡 모음 같습니다. 수상 사이트의 9~12px 고정폭 번호 캡션 대신 번호 없는 본문 서체·본문 크기 한 줄을 씁니다.

**가로 갤러리**

- *사용:* 제품·방·행사·팀처럼 어느 순서로든 둘러보는 모음입니다.
- *배치:* 폭 25~35% 카드(1440에서 435×326, 간격 20px, 3개와 네 번째 일부), 또는 고정 높이·다른 폭의 띠(조사 576px), 또는 중앙 슬라이드 약 73%와 양옆 170~180px 노출입니다. 오른쪽이 잘려 더 있음을 보여야 합니다. 이미지 마키는 한 바퀴 60~120초로 천천히 움직입니다.

- *실패:* 화살표만 있고 드래그·스와이프 없음, 읽어야 할 항목의 마키, 핵심 사진 하나를 캐러셀 안에 숨김입니다.

**고정 사진 위로 올라오는 패널**

- *사용:* 장을 바꾸며 사진은 고정하고 다음 절이 올라옵니다.
- *배치:* 사진은 100vh sticky, 다음 절 바탕이 전폭으로 올라옵니다. 윗변은 직선 또는 대상 고유 형태(조사에는 건물 창의 아치)입니다. 여기서는 직각 모서리 단색 패널을 쓰고 둥근 시트 상단·반투명 유리는 쓰지 않습니다.
- *휴대폰:* 동일합니다.
- *실패:* 앞 카드가 얇게 남는 5~6장 카드 덱, 목적 없는 쌓기입니다.

**균등 그리드**

- *사용:* 상점 제품군·팀·메뉴·전체 작업 목록 같은 아카이브만 해당합니다(layout.md §5).
- *배치:* 2·3·4열 동일 셀, 간격 8~16px, 비율 하나(주로 4:5), 사진 아래 캡션입니다.
- *휴대폰:* 제품은 2열, 작업·사람은 1열입니다.
- *실패:* 같은 크기 기능 카드 3장. 조사에서 흔한 사진 아래쪽 어두운 그라디언트 위 라벨 대신 여기서는 라벨을 사진 아래 놓습니다.

**호버 미리보기 목록**

- *사용:* 이름도 사진만큼 중요한 프로젝트·고객 8개 이상 목록입니다.
- *배치:* 행 피치 45~80px, 이름 30~60px입니다. 한 번에 사진 하나, 폭 약 3분의 1·16:9 또는 높이 300~450px 세로 사진을 고정 위치(50%선 오른쪽 절반 또는 중앙)에 두고 0.3초 안에 교체합니다. 마우스 없는 버전은 중앙 고정 사진을 지나는 이름에 맞춰 바꿉니다. 조사에서는 사진이 이름 위에 있지만 여기서는 대형 글자를 덮지 않으므로 이름이 앞을 지납니다.
- *휴대폰:* 호버 없이 행마다 약 100px 썸네일 또는 스크롤 버전입니다.
- *실패:* 터치에서 안 나타나는 사진. 수상 사이트의 가는 구분선 대신 공간으로 나누고 활성 행은 잉크·바탕 변화로 구별합니다.

**바탕 위 사진 하나 또는 주장 옆 작은 사진 하나**

- *사용:* 인물·사물 하나로 쉬어 가거나 작은 사진으로 주장에 얼굴을 부여합니다.
- *배치:* 사진에서 딴 바탕색 위 중앙 3:4·뷰포트 높이 75%, 또는 폭 7~26%(108~374px) 작은 사진을 48~136px 문장의 옆·위·행 사이에 한 행과 맞춥니다.
- *휴대폰:* 사진을 문장 위에 폭 60~100%로 둡니다.
- *실패:* 모든 사진의 기본값으로 사용해 사방 동일 여백이 생기는 경우입니다(5절).

**단어 사이 작은 사진**

- *사용:* 재료·사람·제품 자체에 관한 문장 하나가 독립 화면을 가질 때입니다.
- *배치:* 같은 촬영 세트의 직각 사진 2~4개를 문장 안에 둡니다. 높이는 대문자 높이~글자 크기 4분의 3, 폭은 그 1~1.5배입니다. 예: 60px 행에 50×46px, 150px 이름의 두 단어 사이 113×75px. 로드 중 줄이 뛰지 않게 크기를 지정합니다.
- *휴대폰:* 텍스트 높이의 인라인 유지입니다.
- *실패:* 4개 초과, 다른 촬영 세트 혼합, 글자에 없는 정보를 사진 조각에만 담는 경우입니다.

**대형 글자 안이나 뒤의 사진**

- *사용:* 제품·건물·사람처럼 사물 자체가 주제일 때입니다.
- *배치:* 150~200px 대형 글자 블록 안 작은 사진 창이 다음 화면으로 열리거나, 사물이 글자 뒤에서 사이·주변으로 보이거나, 글자를 덮지 않고 단어 끝에 닿습니다. 조사에서는 사물이 글자 한두 개를 덮거나 글자 행이 사각 사진 뒤로 지나가지만 여기서는 제목 위에 아무것도 놓지 않습니다. 검사기는 대형 글자의 5분의 1 이상이 가려지면 실패하므로 글자를 앞에 둡니다.
- *휴대폰:* 글자 약 15vw로 유지하며 단어가 읽히는지 확인합니다.
- *실패:* 사물이 글자를 덮거나 사진이 글자를 밀고 왜곡하는 경우입니다.

**단색 바탕 누끼 사물**

- *사용:* 제품·사물입니다. 표의 평균 점수가 가장 높으며 상위 36개 중 7개에 있습니다.
- *배치:* 사물 자체 색에서 가져온 단색 바탕에 폭 35~60%, 바닥에 닿거나 한쪽 밖으로 넘기고 글자는 뒤·옆에 둡니다.
- *휴대폰:* 제목 아래 폭 80~90%입니다.
- *실패:* 바닥 없이 허공에 뜬 렌더, 누끼에 추가한 그림자입니다. 사진에 찍힌 접촉 그림자만 유지하고 받침 그림자를 추가하지 않습니다.

**흩어진 콜라주**

- *사용:* 아카이브·인쇄 잡물·작은 것이 많은 축제에 드물게 씁니다. 최하위에서도 상위만큼 흔합니다.
- *배치:* 중앙 제목 주변에 몇 가지 크기의 100~300px 사진 6~16개를 두되 덮지 않습니다.
- *휴대폰:* 한 열의 겹치는 쌍으로 다시 쌓습니다.
- *실패:* 조사에서 흔한 기울인 인쇄물·스티커의 어긋난 그림자는 허용 처리가 아니며(6절), 사진이 글자를 가로지르면 안 됩니다.

**구석 고정 작은 카드**

- *사용:* 영상 모음·다음 항목으로 안내하는 상시 표식입니다.
- *배치:* 약 216×144~240×140, 구석에서 30~43px, 페이지당 하나입니다.
- *휴대폰:* 없애거나 일반 흐름에 넣습니다.
- *실패:* 아래로 내용이 스크롤해 지나가거나 둘째 카드를 추가하는 경우입니다.

**3D 갤러리**

- *형태:* WebGL 장면의 고리·구·나선·터널 위 이미지를 휠·드래그로 돌립니다.
- *조사:* 12개 중 최하위 16개에 4개가 있으며 평균 점수 7.30 대 7.44, 사용성 5.9 대 6.35입니다.
- *여기서는:* 만들지 않습니다. 같은 사진을 미리보기 목록·가로 갤러리로 보여 줍니다.

### 영상

**조사 측정값.**

- 91개 중 38개(42%)가 사용합니다. 상위 36개 중 18, 중간 39개 중 19, 최하위 16개 중 1입니다. 사용 사이트의 클립 중앙값은 3~4개(중간 50% 1~8)입니다.
- 약 4분의 1은 첫 화면 절반 이상이 영상이며 거의 모두 전면입니다.
- 길이 중앙값 10초, 중간 50% 5~14초, 61%는 10초 이하, 88%는 20초 이하입니다.
- 모든 장식 영상은 음소거·반복·인라인이며 제어 UI가 없습니다. 44%에 autoplay 속성이 있고 나머지는 대개 화면 진입 시 스크립트로 시작합니다.
- 31%(38개 사이트 중 13개)만 포스터가 있습니다. 나머지는 재생 전 빈 회색 상자로 보여 평가단이 첫 화면 결점으로 기록했습니다. 여기서는 포스터가 필수입니다(11절).
- 원본은 1920×1080이 가장 흔하고 다음은 1280×720입니다. 휴대폰·세로 타일은 450×800·540×960 세로 영상입니다. 원본 폭 중앙값은 1080px입니다.
- 표시 비율: 16:9 41%, 정사각 19%, 세로(4:5~9:16) 25%, 4:3·3:2 12%. 75%가 직각이고 나머지는 8px 이하 또는 20~32px입니다. `object-fit: cover` 84%, contain 16%(제품 띠·레터박스 영상)입니다.

**배치.**

- **히어로 배경:** 전면 cover, 이동·확대 시 변이 드러나지 않게 1~25% 크게 둡니다. 느린 원테이크 또는 1~2초마다 자르는 몽타주입니다.
- **사진처럼 인라인:** 분할·타일·카드에서 폭 약 3분의 1(중앙값 33%, 중간 50% 24~45%)입니다. 이 중 3분의 1은 폭 4분의 1 미만, 전폭은 10% 미만입니다. 물·피부·빛·회전 사물처럼 거의 정지한 느린 대상은 살아 있는 사진처럼 정지 이미지 사이에 어울립니다.
- **확대 프레임:** 위 항목처럼 영상 모음에 씁니다.
- **구석 고정 카드:** 작은 영상 하나를 둡니다.
- **호버:** 2~3개 사이트만 목록·색인에서 사용합니다. 중요한 영상은 휴대폰에 없는 호버에만 의존하지 않습니다.
- **전체 영화:** 약 10개 사이트가 재생 버튼 뒤 제어 가능한 플레이어로 제공하며 어느 것도 자동 재생하지 않습니다.
- **소리:** 6개 사이트가 토글 뒤 소리를 제공하며 처음부터 소리 나는 영상은 없습니다.

**텍스트 배치.**

- 첫 화면 전면 이미지·영상 뒤에 글자를 둔 약 30개 중 약 14개는 글자 위치의 어두운 색보정에 의존해 직접 놓고, 약 10개는 밝기 절반·30~40% 어두운 층·하단 180~590px 어두운 페이드로 어둡게 하며, 약 6개는 이미지 위쪽 또는 단색 카드에 분리합니다.
- 보통 47~136px 이름·제목과 짧은 한 줄을 왼쪽 아래·중앙에 둡니다. 영상·복잡한 사진 위 11~14px 본문은 상위 사이트에서도 결점으로 지적됐습니다.
- 여기서는 최대 제목·한 줄·동작 하나이며 본문은 금지합니다. 포스터만이 아닌 전체 루프에서 글자 위치의 대비를 검사하고 한 프레임이라도 4.5:1(24px 이상 3:1) 미만이면 6절 차광막·단색 띠를 씁니다.

**휴대폰.** 별도 세로 원본 또는 대상에 맞춘 `object-position`으로 전면 세로 자르기를 하고 안쪽 프레임도 전면으로 바꿉니다. 조사 중 한 사이트는 글자가 더 넓은 사진 영역을 덮는 휴대폰에서만 40% 차광막을 추가했습니다.

### 자르기와 처리

- **비율:** 이미지·클립 1356개에서 4:5 21%, 16:9 19%, 1:1 16%, 16:10 10%, 3:2 7%, 2:3 5%, 4:3 5%, 5:4 4%, 3:4 3%, 2:1보다 가로 6%, 9:16 이상 세로 3%입니다. 가로 52%, 세로 33%, 정사각 15%입니다.
- **두 비율이 대부분 담당:** 4장 이상 사이트의 상위 두 비율이 76%를 차지합니다. 나머지(전체 중앙값 5종)는 가로 연작의 세로 인물 하나·전폭 띠 하나처럼 이유 있는 예외입니다.
- **94% 직각:** 사진 있는 68개 중 62개는 80% 이상 직각입니다. 둥근 경우 3분의 2는 5px 이하, 카드 UI는 20~32px이며 사이트마다 하나의 값입니다.
- **Cover:** 78%, contain 10%(타일 위 제품·레터박스 영상)입니다.
- **원본 그대로:** CSS 필터는 9개 사이트만 주로 호버에 사용합니다. 일부는 흑백 사진 세트, 2개는 종이 스캔을 multiply로 얹습니다. 여럿은 UI를 흑백·회색으로 두고 사진에 모든 색을 맡깁니다.
- **흔하지만 여기서는 허용하지 않는 처리**(6절): 약 3분의 1의 전면 고정 노이즈 층, 듀오톤·착색 사진, 이미지 뒤 흐린 복사본 광채, 기울인 인쇄물·스티커의 어긋난 그림자입니다.
- **이동 거리만큼만 확대:** 22개 사이트가 스크롤로 사진을 움직이며 1~25% 크게 만듭니다. 화면당 하나를 이동 거리만큼만 크게 합니다.
- **해상도:** 제공 폭 중앙값은 CSS 폭의 1.9배지만 17%는 표시보다 작고 전폭 사진 중앙값도 1440px뿐입니다. 여기서는 CSS 폭 두 배, 약 2400px 상한입니다(4절).

### 사진 위 글자

- 조사에서는 자주 쓰지만 검사는 드뭅니다. 약 28개 메모가 차광막 없이 직접 놓은 글자를 기록했고 16개 사이트가 사진 위에서 잃어버린 글자 때문에 지적받았습니다. 8~14px 라벨·본문, difference 혼합·배경 없는 내비게이션이 해당합니다.
- 잘 된 경우 대형 글자가 하늘·어두운 벽·그늘처럼 조용한 곳의 구석·변에 붙습니다. 다른 방식은 사진 위 바탕색 단색 카드에 제목을 두거나 페이지와 이어지는 이미지 흰 부분에 글자를 두는 것입니다.
- 여기서는 대형 글자·짧은 한 줄·동작 하나만 둡니다. 본문·캡션·라벨은 옆·아래입니다. 실제 위치의 대비를 4.5:1(24px 이상 3:1)로 측정합니다. 실패하면 조용한 영역, 바탕색 단색 카드, 6절 차광막 중 하나를 씁니다. 사진 위를 지나는 고정 내비게이션은 단색 띠를 두거나 아래로 스크롤할 때 숨깁니다.

### 생성기 규칙

1. **페이지 약 3분의 1이 이미지:** 스크롤 면적의 30~40%, 최소 네 화면 중 하나는 이미지 없음입니다(상위 30%·28%).
2. **화면을 이끌거나 작게:** 주 이미지는 화면 60% 이상, 강조 이미지는 10% 미만입니다. 20~40% 사진 화면을 연속하지 않습니다. 조사상 42%는 0%, 19%는 90% 이상입니다.
3. **페이지당 3~5개 배치:** 이웃 절에서 반복하지 않습니다. 2개 이하는 평균 7.31점, 3개 이상 약 7.5점입니다.
4. **6~12장, 최소 4장:** 조사 중앙값 7장, 상위 4~27장, 최하위 2장입니다.
5. **75% 이상을 두 비율로:** 조사 76%, 세 번째는 의도한 예외만입니다. 기본은 인물 4:5, 풍경 16:9·3:2입니다.
6. **모두 직각:** 조사 94%. 방향이 요구하면 모든 이미지·클립에 반지름 4px 하나를 씁니다.
7. **분할 사진 폭 42~50% 또는 3분의 2:** 절 전체 높이·바깥 변 뷰포트 접촉·글자 50%선 시작입니다. 휴대폰은 이미지 먼저 전폭입니다.
8. **전면 띠 100%폭·100~150vh:** 3~4화면마다 한 번, 패럴랙스 확대 최대 10%, 글자는 구석에서 최소 32px 안쪽입니다. 휴대폰은 전면 세로로 자릅니다.
9. **확대 프레임은 페이지당 한 번:** 폭 35~50%에서 전체 화면까지 720~2700px 스크롤하며 같은 화면의 다른 것은 움직이지 않습니다.
10. **가로 갤러리 3개와 네 번째 일부:** 폭 25~35%, 간격 16~20px입니다. 휴대폰은 폭 75~80% 하나와 다음 일부입니다.
11. **화면당 움직이는 그림 하나:** 5~15초(중앙값 10초), 음소거·반복·인라인·포스터·화면 밖 정지입니다. 히어로 1920×1080·10MB 미만, 인라인 1280×720 이하·5MB 미만입니다.
12. **사진 위에는 대형 글자만:** 최대 제목·한 줄·동작 하나, 전체 루프의 실제 위치 대비를 측정합니다. 16px 이상 본문은 옆·아래에 두며 사진 위에 놓지 않습니다.
