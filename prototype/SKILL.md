# 프로토타입

프로토타입은 **질문에 답하는 일회용 코드**입니다. 질문에 따라 형태를 정합니다.

## 경로 선택

사용자의 요청과 주변 코드를 보고 어떤 질문에 답할지 파악합니다. 사용자와 대화할 수 있다면 물어봅니다.

- **"이 로직이나 상태 모델이 적절한가?"** → [LOGIC.md](LOGIC.md). 자유 조작 버튼과 탭으로 구분된 안내형 시나리오가 있는 공유 가능한 HTML 파일 하나를 만듭니다. 문서만으로 판단하기 어려운 사례를 상태 머신에 적용하며, 개발자가 아닌 사람도 조작할 수 있어야 합니다.
- **"어떤 모습이어야 하나?"** → [UI.md](UI.md). 하나의 라우트에 서로 크게 다른 UI 시안 여러 개를 만들고, URL 검색 매개변수와 화면 하단에 떠 있는 바로 전환할 수 있게 합니다.

두 경로의 결과물은 크게 다릅니다. 질문이 모호하고 사용자에게 물을 수 없다면 주변 코드에 맞는 경로를 고릅니다(백엔드 모듈 → 로직, 페이지나 컴포넌트 → UI). 프로토타입 상단에 그 가정을 명시합니다.

## 공통 규칙

1. **처음부터 일회용으로 만들고 명확히 표시합니다.** 실제로 사용될 모듈이나 페이지 가까이에 두되, 이름만 봐도 프로덕션 코드가 아닌 프로토타입임을 알 수 있게 합니다. 일회용 UI 라우트는 기존 라우팅 관례를 따릅니다.
2. **실행이 쉬워야 합니다.** UI 프로토타입은 프로젝트 작업 실행기의 명령 하나(`pnpm <name>`, `python <path>`, `bun <path>` 등)로 시작합니다. 로직 데모는 더블클릭으로 열 수 있는 HTML 파일 하나입니다.
3. **기본적으로 데이터를 저장하지 않습니다.** 상태는 메모리에 둡니다. 저장 동작 자체가 검증 대상이라면, 이름에 "PROTOTYPE, 삭제 가능"을 표시한 임시 DB나 로컬 파일을 사용합니다.
4. **마감 작업은 생략합니다.** 실행에 필요한 수준을 넘는 테스트, 오류 처리, 추상화는 추가하지 않습니다. 빠르게 배우는 것이 목적입니다.
5. **상태를 드러냅니다.** 로직 조작이나 UI 시안 전환 후마다 관련 상태 전체를 출력하거나 렌더링합니다.
6. **완료 후 기록합니다.** 검증된 결정은 실제 코드에 반영합니다. 프로토타입 자체도 일차 자료로 보존합니다. 메인 브랜치 밖의 일회용 브랜치에 커밋하고 구현 이슈에 그 브랜치를 가리키는 링크를 남깁니다. 이슈나 커밋에 해결한 질문과 결론을 기록합니다. 메인 브랜치에는 검증된 결정만 남깁니다.
