# 로직 프로토타입

누구나 버튼을 눌러 상태 모델을 조작할 수 있는 **공유 가능한 데모**인 독립 HTML 파일 하나를 만듭니다. 비즈니스 로직, 상태 전환, 데이터 형태를 문서에서만 판단하기 어려울 때 사용합니다.

설치 없이 파일 하나만 전달하면 디자이너, 기획자, 도메인 전문가도 직접 모델을 확인할 수 있습니다. 따라서 코드 용어가 아닌 그들의 도메인 언어를 사용합니다.

## 적합한 경우

- "X 다음 Y가 일어나는 예외 상황을 이 상태 머신이 처리할까?"
- "이 데이터 모델로 ...인 경우를 표현할 수 있을까?"
- "구현 전에 API가 어떤 모습이어야 할지 직접 느껴보고 싶어."
- **버튼을 눌러 상태 변화를 보고 싶은** 경우

보이는 모습에 관한 질문이라면 [UI.md](UI.md)를 사용합니다.

## 절차

### 1. 질문 명시

코드를 작성하기 전에 검증할 상태 모델과 질문을 데모 상단의 **보이는 소개 문단**에 적습니다. 주석에만 두지 않습니다. 사용자가 지금 살펴보든 나중에 다시 열든 질문을 확인할 수 있어야 합니다.

### 2. 로직을 옮길 수 있는 모듈로 분리

질문에 답하는 실제 로직을 나중에 코드베이스로 옮길 수 있도록 하나의 `<script>` 블록 안에 작고 순수한 모듈로 작성합니다. 주변 페이지는 일회용이지만 로직 모듈은 재사용할 수 있어야 합니다.

질문에 맞는 형태를 고릅니다.

- **순수 리듀서**: `(state, action) => state`. 행동이 별개 이벤트이고 상태가 하나의 값일 때 적합합니다.
- **상태 머신**: 상태와 전환을 명시합니다. 현재 어떤 행동이 허용되는지가 질문의 일부일 때 적합합니다.
- **평범한 데이터 타입에 대한 순수 함수 몇 개**: 암묵적인 현재 상태 없이 변환만 있을 때 적합합니다.
- **메서드 경계가 분명한 클래스나 모듈**: 로직이 지속적인 내부 상태를 실제로 소유할 때 적합합니다.

페이지에 연결하기 쉬운 형태가 아니라 질문에 맞는 형태를 선택합니다. 로직에는 DOM, `document`, 버튼 핸들러를 넣지 않습니다. 페이지가 로직을 호출하는 단방향 관계를 유지합니다. 그러면 검증된 리듀서, 머신, 함수 묶음을 실제 모듈로 옮길 수 있습니다.

### 3. 공유 가능한 HTML 파일 만들기

HTML, CSS, JS를 모두 넣은 파일 하나로 만듭니다. 프레임워크, 번들러, 서버는 사용하지 않습니다. 더블클릭으로 열리고 파일 자체를 전달할 수 있어야 합니다.

개발자가 아닌 사람을 위해 모든 버튼과 상태를 **도메인 언어**로 설명합니다. 위에서 아래로 다음 순서로 구성합니다.

1. **제목과 한 줄 설명**: 무엇을 탐색할 수 있는지 설명합니다.
2. **현재 상태**: 관련 상태 전체를 JSON 원문 대신 읽기 쉬운 필드로 표시합니다. 클릭할 때마다 다시 렌더링하고 필요하다면 바뀐 점을 알려줍니다.
3. **자유 조작 버튼**: 각 행동에 버튼 하나를 항상 표시합니다. 클릭하면 행동을 적용하고 상태를 다시 그립니다.
4. **안내형 시나리오**: 시나리오마다 탭 하나를 둡니다. 상황과 관찰할 점을 짧게 설명하고 순서대로 누를 **실제 버튼**을 배치합니다. 각 단계 버튼은 행동을 실행하고 다음 단계로 이동합니다. 시나리오를 시작하면 알려진 초기 상태로 재설정해 매번 같은 방식으로 실행되게 합니다.

정상 경로, 까다로운 예외, 허용되지 않아야 하는 시도처럼 문서에서 판단하기 어려운 경우를 시나리오로 고릅니다. 서체와 여백을 정돈하고 강조색 하나만 씁니다. 상태와 버튼을 가리는 애니메이션이나 장식은 넣지 않습니다.

### 4. 전달

파일을 보내거나 열어 보여줍니다. 사용자가 시나리오와 자유 조작을 거치면서 "이게 가능하면 안 되는데" 또는 "X가 다를 줄 알았는데"라고 느끼는 순간이 바로 아이디어의 오류를 찾은 것입니다. 새 행동이나 시나리오가 필요하면 추가합니다.

### 5. 답과 프로토타입 기록

질문에 답한 뒤 [SKILL.md](SKILL.md)의 방법대로 결론과 프로토타입을 기록합니다. 검증된 로직은 실제 모듈에 반영합니다. HTML 파일은 일차 자료로서 별도 일회용 브랜치에 보관하면 나중에도 쉽게 다시 실행할 수 있습니다.

## 안티패턴

- **테스트를 추가하지 않습니다.** 테스트가 필요할 정도라면 프로토타입이 아닙니다.
- **실제 DB를 연결하지 않습니다.** 저장 자체가 질문이 아니라면 메모리를 사용합니다.
- **일반화하지 않습니다.** 미래 기능을 가정하지 않고 질문 하나에 답합니다.
- **로직과 페이지를 섞지 않습니다.** 순수 모듈에서 DOM이나 버튼 핸들러를 참조하면 옮길 수 없습니다.
- **프레임워크, 번들러, 서버를 사용하지 않습니다.** 수신자가 더블클릭하는 파일 하나여야 합니다.
- **HTML 외피를 프로덕션에 넣지 않습니다.** 유지할 가치는 검증된 로직에 있습니다.
