하네스 내장 서브에이전트 도구로는 dsh를 부를 수 없다. `scripts/run.sh`를 셸 명령으로 백그라운드 실행한다. 기본 모델은 `deepseek-flash`, 사고 수준 high다(`assets/deepseek-flash-high.yml`).

**메인이 쓰는 토큰은 메인 턴 수 × 컨텍스트 크기로 정해진다.** 턴마다 컨텍스트 전체를 캐시에서 다시 읽기 때문이다. 일을 넘기는 효과는 메인 턴을 줄일 때만 난다. 아래 절차는 메인 턴과 메인이 읽는 양을 줄이는 순서로 짜여 있다.

## 절차

### 1. 나눈다

| dsh에 넘긴다 | 메인에 남긴다 |
|---|---|
| 구현, 테스트 작성·실행 | 요구 해석, 설계·권한 판단 |
| 집계·조사, 로그 분석 | 명세 작성, 리뷰 지적의 수용 여부 |
| 영상 녹화·내레이션, 보고서 초안 | 프레임·스크린샷 판독, 커밋, 샌드박스 밖 쓰기 |

완료 기준: 메인에 남은 일이 판단과 확인뿐이다.

### 2. 명세를 파일로 쓴다

flash는 명세를 충실히 따르고, 명세의 틀린 지시도 그대로 구현한다. 그래서 명세에 적는 사실은 메인이 원본에서 직접 확인한 것이어야 한다. 명세의 품질이 재작업 횟수를 정한다.

명세에 넣는 것:

- 작업 폴더와 건드리면 안 되는 경로·DB
- 고칠 파일, 함수, 행 근처, 입력별 기대 결과
- 고치면 안 되는 범위와 "커밋하지 않는다"
- 실행할 검증 명령 전체
- 일부러 깨 보아 실패를 확인할 대조 한 건(테스트가 있는 작업)
- 보고 형식: "15줄 이내, 항목별 결과, 테스트별 수치, 명세와 다른 점, 멈춘 항목. 코드와 로그를 붙이지 않는다."

저장소에 남으면 안 되는 환경 값(로컬 DB 이름, 주소)이 있으면 명시한다. 명세에 없으면 코드에 박아 넣는다.

완료 기준: dsh가 되묻지 않고 끝낼 수 있고, 결과가 맞는지 메인이 명령 몇 개로 판정할 수 있다.

### 3. 백그라운드로 실행한다

```sh
~/.agents/skills/dsh-subagent/scripts/run.sh <작업폴더> <명세.md> <출력.jsonl> [세션ID]
```

셸 도구의 백그라운드 실행(Claude Code는 `run_in_background: true`)으로 호출하고 완료 알림을 기다린다. 백그라운드 실행이 없는 하네스에서는 전경으로 실행한다. 기다리는 동안 메인은 다른 일을 하거나 턴을 끝낸다. 상태를 확인하려고 턴을 쓰지 않는다. 서로 다른 폴더의 작업은 병렬로 돌릴 수 있다.

완료 알림은 백그라운드 명령마다 메인 턴을 하나씩 만든다. 함께 끝나도 되는 작업은 셸 스크립트 하나에 `&`와 `wait`로 묶어 백그라운드 명령 하나로 띄운다. 리뷰 세 종을 따로 띄우면 알림 턴이 세 번 든다.

`run.sh`는 세션 ID, 스텝·도구 수, 토큰 합계, 마지막 컨텍스트 크기, 최종 보고만 출력한다. `.jsonl` 원문은 수백 KB이므로 메인에서 열지 않는다. 특정 내용이 필요하면 스크립트로 걸러 읽는다.

### 4. 직접 확인한다

최종 보고는 주장일 뿐이다. 한 메시지 안에서 묶어 확인한다.

- `git diff --stat`으로 범위 밖 변경이 없는지 본다.
- 검증 명령의 종료 코드와 수치를 메인이 실행해 보거나 증거 로그에서 읽는다.
- 금지한 문자열·경로가 diff에 없는지 grep으로 본다.

코드 전체 판단은 독립 리뷰에 맡긴다. 메인이 diff 전체를 읽지 않는다. 이번 변경이 권한·개인정보·이관을 건드리면 리뷰 결과를 근거로 필요한 곳만 읽는다.

완료 기준: 보고의 수치를 메인이 다른 경로로 한 번 확인했다.

### 5. 고칠 것을 넘긴다

| 상황 | 방법 |
|---|---|
| 같은 작업의 후속 수정 | 세션 ID를 넘겨 이어서 시킨다. 다시 파악하지 않아 가장 빠르다 |
| 마지막 컨텍스트가 50만을 넘음 | 새 세션을 만들고 명세에 필요한 경로를 다 적는다. 이전 세션의 금지 규칙을 뒤집을 때도 새 세션이 안전하다 |
| 같은 실패가 3회 반복 | 넘기기를 멈추고 메인이 원인을 판단한다. 5회면 실패 보고서를 쓴다 |
| `QUOTA: Insufficient Balance` | 사용자가 DeepSeek 잔액을 충전해야 풀린다. 재시도하지 말고 사용자에게 알린다. 멈춘 작업은 산출물 위치와 남은 일을 적어 메인 하네스의 저비용 서브에이전트로 이어 간다 |

리뷰 지적은 묶어서 한 번에 넘긴다. 지적마다 턴을 쓰지 않는다.

## 메인 토큰을 줄이는 규칙

- 독립적인 확인은 한 메시지에 묶는다. 턴 하나가 곧 컨텍스트 전체다.
- 긴 출력은 파일로 받고 수치만 뽑는다.
- 큰 파일과 보고서는 메인에서 읽지 않는다. 필요한 행만 본다.
- 프레임 판독은 장면당 한 장, 위험한 장면만 메인이 본다. 이미지는 컨텍스트를 끝까지 따라다닌다. 그래도 실제 데이터가 화면에 나오는 장면은 건너뛰지 않는다. 자동 판정이 통과해도 개인 글이 그대로 찍혀 있는 경우를 메인이 프레임에서 잡았다.
- 메인 하네스 모델이 맡아야 하는 리뷰는 리뷰의 난이도와 위험도를 보고 에이전트가 판단해 적절한 수준의 모델과 사고 수준으로 돌린다. 최상위 모델을 기본값으로 쓰지 않는다. 최상위 모델(Claude Opus) 리뷰 네 번의 출력 합계 18.5만은 당시 메인 세션 전체보다 많았다(2026-11-02 실측).

## 샌드박스 한계

- 쓰기는 작업 폴더와 `/private/tmp`만 된다. 메인 체크아웃, `~/.agents`, git 무시 문서처럼 밖에 있는 파일은 메인이 고친다.
- 워크트리의 `.git`은 폴더 밖이므로 커밋은 메인이 한다.
- 이미지를 볼 수 없다. 영상과 화면은 찍을 수 있어도 판정은 메인이 한다.
- mysql, wp-cli, curl, Chrome(playwright-core), ffmpeg는 된다.
- DB를 쓰는 작업은 다른 세션과 겹치지 않게 전용 복제본을 준다.
