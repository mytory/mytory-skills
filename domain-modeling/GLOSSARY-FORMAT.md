# GLOSSARY.md 형식

## 구조

```md
# {컨텍스트 이름}

{이 컨텍스트가 무엇이고 왜 존재하는지 설명하는 한두 문장}

## 용어

**주문**:
{용어를 설명하는 한두 문장}
_피할 표현_: 구매, 거래

**청구서**:
배송 후 고객에게 보내는 결제 요청.
_피할 표현_: 고지서, 결제 요청서

**고객**:
주문하는 개인 또는 조직.
_피할 표현_: 클라이언트, 구매자, 계정
```

## 규칙

- **명확히 선택하세요.** 같은 개념을 나타내는 단어가 여러 개라면 가장 적합한 하나를 고르고 나머지를 `_피할 표현_` 아래에 적습니다.
- **정의를 간결하게 쓰세요.** 한두 문장을 넘기지 않습니다. 무엇을 *하는지*가 아니라 무엇*인지* 정의합니다.
- **프로젝트 컨텍스트에 고유한 용어만 넣으세요.** 타임아웃, 오류 유형, 유틸리티 패턴 같은 일반 프로그래밍 개념은 프로젝트에서 많이 쓰더라도 넣지 않습니다. 추가하기 전에 이 컨텍스트에 고유한 개념인지, 일반적인 프로그래밍 개념인지 묻습니다. 전자만 넣습니다.
- **자연스러운 묶음이 생기면 소제목으로 분류하세요.** 모든 용어가 하나의 영역에 속한다면 평면 목록으로 충분합니다.

## 단일 컨텍스트와 다중 컨텍스트 저장소

**단일 컨텍스트(대부분의 저장소):** 루트에 `GLOSSARY.md` 하나를 둡니다.

**다중 컨텍스트:** 루트의 `GLOSSARY-MAP.md`에 각 컨텍스트의 위치와 관계를 적습니다.

```md
# 용어집 지도

## 컨텍스트

- [주문](./src/ordering/GLOSSARY.md): 고객 주문을 접수하고 추적함
- [청구](./src/billing/GLOSSARY.md): 청구서를 발행하고 결제를 처리함
- [배송](./src/fulfillment/GLOSSARY.md): 창고 출고와 배송을 관리함

## 관계

- **주문 → 배송**: 주문 컨텍스트가 `OrderPlaced` 이벤트를 발행하면 배송 컨텍스트가 이를 받아 출고를 시작함
- **배송 → 청구**: 배송 컨텍스트가 `ShipmentDispatched` 이벤트를 발행하면 청구 컨텍스트가 이를 받아 청구서를 생성함
- **주문 ↔ 청구**: `CustomerId`와 `Money` 타입을 공유함
```

스킬은 다음 기준으로 구조를 판단합니다.

- `GLOSSARY-MAP.md`가 있으면 읽어서 컨텍스트를 찾습니다.
- 루트의 `GLOSSARY.md`만 있으면 단일 컨텍스트입니다.
- 둘 다 없다면 첫 용어가 확정될 때 루트에 `GLOSSARY.md`를 만듭니다.

컨텍스트가 여러 개라면 현재 주제가 어느 컨텍스트에 해당하는지 추론합니다. 불명확하면 사용자에게 묻습니다.
