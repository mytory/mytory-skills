# 이슈로 변환

수직 슬라이스(트레이서 불릿)를 사용해 계획을 독립적으로 가져갈 수 있는 이슈로 분해하세요.

이슈 트래커와 분류 라벨 어휘가 제공되어 있어야 합니다 — 없으면 `/setup-matt-pocock-skills`를 실행하세요.

## 절차

### 1. 맥락 수집

현재 대화 컨텍스트에 이미 있는 내용으로 작업하세요. 사용자가 인자로 이슈 참조(이슈 번호, URL, 경로)를 전달했다면, 이슈 트래커에서 가져와 전체 본문과 댓글을 읽으세요.

### 2. 코드베이스 탐색 (선택)

아직 코드베이스를 탐색하지 않았다면, 현재 코드 상태를 이해하기 위해 탐색하세요. 이슈 제목과 설명은 프로젝트의 도메인 용어집을 사용하고, 다루는 영역의 ADR을 존중해야 합니다.

### 3. 수직 슬라이스 초안 작성

계획을 **트레이서 불릿** 이슈로 분해하세요. 각 이슈는 모든 통합 계층을 끝에서 끝까지 관통하는 얇은 수직 슬라이스여야 하며, 한 계층만 다루는 수평 슬라이스가 아니어야 합니다.

슬라이스는 'HITL' 또는 'AFK'일 수 있습니다. HITL 슬라이스는 아키텍처 결정이나 디자인 리뷰 같은 사람의 개입이 필요합니다. AFK 슬라이스는 사람 개입 없이 구현 및 병합이 가능합니다. 가능한 한 AFK를 HITL보다 우선하세요.

<vertical-slice-rules>
- 각 슬라이스는 모든 계층(스키마, API, UI, 테스트)을 관통하는 좁지만 완전한 경로를 제공합니다
- 완료된 슬라이스는 그 자체로 데모나 검증이 가능합니다
- 두꺼운 슬라이스 몇 개보다 얇은 슬라이스 여러 개를 선호합니다
</vertical-slice-rules>

### 4. 사용자 확인

제안된 분할을 번호가 매겨진 목록으로 제시하세요. 각 슬라이스마다 보여주세요:

- **제목**: 짧은 설명적 이름
- **유형**: HITL / AFK
- **차단 요소**: 먼저 완료되어야 하는 다른 슬라이스(있는 경우)
- **대상 사용자 스토리**: 이 슬라이스가 다루는 사용자 스토리 (원본 자료에 있는 경우)

사용자에게 물어보세요:

- 세분화 수준이 적절한가요? (너무 큼 / 너무 작음)
- 의존성 관계가 올바른가요?
- 병합하거나 더 분할해야 할 슬라이스가 있나요?
- HITL과 AFK가 올바르게 표시되었나요?

사용자가 분할을 승인할 때까지 반복하세요.

### 5. 이슈 트래커에 게시

승인된 각 슬라이스에 대해 이슈 트래커에 새 이슈를 게시하세요. 아래 이슈 본문 템플릿을 사용하세요. 이 이슈들은 AFK 에이전트가 작업할 준비가 된 것으로 간주되므로, 별도 지시가 없는 한 올바른 분류 라벨과 함께 게시하세요.

의존성 순서(차단하는 것 먼저)로 이슈를 게시하여 "차단 요소" 필드에 실제 이슈 식별자를 참조할 수 있게 하세요.
