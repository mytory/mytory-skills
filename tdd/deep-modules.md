# 깊은 모듈

"소프트웨어 설계 철학"에서:

**깊은 모듈** = 작은 인터페이스 + 많은 구현

```
┌─────────────────────┐
│   작은 인터페이스   │  ← 적은 메서드, 단순한 매개변수
├─────────────────────┤
│                     │
│                     │
│   깊은 구현         │  ← 복잡한 로직이 숨겨짐
│                     │
│                     │
└─────────────────────┘
```

**얕은 모듈** = 큰 인터페이스 + 적은 구현 (피해야 함)

```
┌─────────────────────────────────┐
│          큰 인터페이스          │  ← 많은 메서드, 복잡한 매개변수
├─────────────────────────────────┤
│  얇은 구현                      │  ← 그냥 통과시킴
└─────────────────────────────────┘
```

인터페이스 설계 시 자문:

- 메서드 수를 줄일 수 있나?
- 매개변수를 단순화할 수 있나?
- 내부에 더 많은 복잡성을 숨길 수 있나?
