# 브라우저 검증 영상

사용자가 영상만 보고 무엇이 어떻게 동작하는지 이해하게 만든다. 조작을 스크립트로 자동 실행해 mp4에 담고, **캡션과 강조 표시**로 지금 무엇을 보고 있고 어디를 봐야 하는지 알려 준다. mp4는 용량 효율적으로 생성한다.

| 종류 | 언제 | 상태 |
|---|---|---|
| 전후 비교 영상 | 화면 버그 수정, 기존 동작 변경 | 수정 전 → 수정 후, 같은 조작 |
| 작동 시연 영상 | 비교할 "수정 전"이 없는 새 화면·기능 | 수정 후 한 상태 |
| 프레젠테이션 영상 | 다른 사람에게 검토 요청, 위험도 높음 | 완성된 HTML 보고서를 절별로 스크롤(아래 "프레젠테이션 영상") |

어느 종류를 찍을지는 `html-work-report` 스킬의 증거 선택표를 따른다. 화면에서 확인할 수 없는 동작(API·배치·DB 로직)은 영상 대신 실행 기록으로 입증한다.

## 도구

- **녹화는 스크립트로 한다. 기본은 Playwright**(`playwright-core`, 시스템 Chrome)이고 번들 헬퍼 `scripts/rec-lib.mjs`가 이것 기준이다. 스크립트로 찍는 이유:
  - 같은 조작을 상태마다 똑같이 반복할 수 있다.
  - 동작 간격을 통제할 수 있다. 에이전트가 도구를 한 명령씩 호출하면 명령 사이에 생각하는 시간이 그대로 정지 화면이 된다.
  - 캡션과 판정을 실제 응답·DB 값에서 계산할 수 있다.
  - 틀리면 한 번에 다시 찍을 수 있다.
- **Agent Browser**(`agent-browser record start <경로>` / `record stop`)로 찍어도 된다. 이때도 명령을 셸 스크립트로 묶어 한 번에 실행한다.
- **탐색**(셀렉터와 흐름 파악, 콘솔·네트워크 확인)은 Agent Browser나 크롬 개발자 도구 MCP가 편하다. 탐색한 뒤 스크립트로 옮긴다.
- 어떤 도구로 찍든 아래 연출·검수 규칙은 같다.

```bash
ffmpeg -version | head -1; ffprobe -version | head -1
npm ls playwright-core || npm i playwright-core   # 작업 폴더(스크래치패드)에 설치. channel: 'chrome'이라 브라우저 다운로드는 필요 없다
```

`rec-lib.mjs`는 `playwright-core`를 import하므로 **복사해 쓰는 작업 폴더에 node_modules가 있어야** 한다.

## 절차

1. **무엇을 보여 줄지 정한다.** 상태 목록(전후 비교: 수정 전 / 수정 후 / 필요하면 중간, 작동 시연: 수정 후 하나)과 모든 상태에서 똑같이 할 조작, 기대 결과를 미리 적는다. 작동 시연은 `example.mjs`의 `states`에 한 상태만 둔다. 다르게 나오면 맞추려 하지 말고 나온 대로 찍고 보고한다.
2. **상태별 서버를 띄운다(전후 비교).** git worktree + 포트 분리, 같은 DB·같은 프론트 빌드. 외부 의존은 별도 목 파일로 대체(원본 설정 불변). 첫 화면에서 스타일이 깨지지 않았는지 확인. 자세히: [references/db-and-servers.md](references/db-and-servers.md)
3. **DB를 바꾸는 재현도 허락을 기다리지 않고 진행한다.** 대신 반드시: 기준값 기록 → **원복 스크립트 먼저** → 상태 사이마다·종료 시(중단 시에도) 원복·비교. 같은 문서 참조.
4. **녹화 스크립트를 쓴다.** `scripts/example.mjs`를 복사해 `TODO(프로젝트)` 부분(로그인, URL, 조작, 판정)을 채운다. 연출 규칙:
   - **캡션**: 구간과 장면마다 "지금 무엇을 보고 있고 어디를 봐야 하는가"를 한두 문장으로 단다. 영상에 박는 방식(`caption`, 기본)과 자막 파일 방식(`saveCaptions` → `.srt`·`.vtt`) 중 고르거나 둘 다 쓴다. [references/captions.md](references/captions.md)
   - **강조 표시**: 봐야 할 요소에 테두리와 번호(`highlight`). 번호별 설명은 핵심을 가리지 않는 패널(`notePanel`)에 둔다.
   - DB 변화가 핵심이면 저장 전후 조회 결과를 `tablePanel`로(바뀐 칸 `이전 → 이후` 강조).
   - **영상은 16:9(1920×1080), 캡션·패널은 화면 캡처 밖에 둔다(기본).** 남색 바탕 위 120px 띠에 캡션, 왼쪽 아래에 브라우저 화면(4:3), 오른쪽에 패널 카드를 여백 24px을 두고 놓는다. 페이지를 가리지 않는다. 페이지 위에 덧그려야 하면(`overlay: true`) 반투명 + 대상과 겹치지 않는 자리에 두고 프레임으로 가림 없음을 확인한다. [references/captions.md](references/captions.md)
   - 뷰포트 1440×1080(4:3, 영상에는 1216×912로 축소), **커서 오버레이**(headless 녹화에는 커서가 안 찍힌다), 동작 사이 0.5~1초, 타이핑은 한 글자씩(`humanType`).
   - **캡션의 숫자·목록은 화면에 보이는 것(뷰포트 안의 보이는 요소)을 기준으로 센다.** 응답 데이터나 일부만 센다면 캡션에 기준을 적는다(예: "웹콘솔 응답 기준 노드 7개", "이번 변경 대상 탭 3개(전체 5개)").
   - **캡션과 주석은 실제 결과에서 계산한다. 하드코딩 금지. 기준이 여럿이면 기준별로 따로 판정.** [references/annotation.md](references/annotation.md)
5. **소리 없는 정지 화면은 최대 5초, 내레이션이 포함된 정지 화면은 최대 30초까지 허용한다.** 읽으라고 멈추는 시간은 기본 최대 5초(`holdToRead`가 강제). 내레이션이 포함된 장면은 `setMaxReadMs(30000)`으로 상한을 30초로 올린다. 내레이션 영상이라도 소리 없는 정지 구간은 5초 기준을 적용한다. 허용 시간을 넘기면 캡션이나 내레이션을 줄이거나 장면을 나눈다.
6. **증거를 파일로 남긴다.** 핵심 요청·응답 JSON(`captureResponse`), 결과 스크린샷, DB 전후 값. 스크린샷은 Playwright가 PNG로 찍으므로 마지막에 **WebP로 변환**한다(`html-work-report` 스킬의 `scripts/to-webp.sh 보고서폴더` — HTML 참조까지 고친다).
7. **검수한다(완료 기준). 하나라도 걸리면 고쳐서 다시 찍는다(DB를 썼으면 원복 먼저).**
   - `ffprobe`로 길이·해상도.
   - `scripts/extract-frames.sh 영상.mp4 폴더 초...`로 구간별 핵심 프레임을 뽑아 **직접 열어 본다**: 캡션·커서·강조한 요소가 보이는가, 글자가 안 잘렸는가, **캡션이 말하는 요소·숫자를 프레임에서 눈으로 셀 수 있는가(가려지지 않았는가, 화면에 보이는 숫자와 같은가)**, 스타일이 깨지거나 로그인 화면만 찍히지 않았는가, **캡션과 주석이 실제 화면과 일치하는가**.
   - **정지 화면 검사**: `scripts/check-freeze.sh 영상.mp4` (기본 5초, 내레이션 영상은 `check-freeze.sh 영상.mp4 30`. 초과 구간의 시작·길이를 출력, 초과가 있으면 종료 코드 1). 걸리면 대기를 줄여 다시 찍거나 그 구간을 잘라 낸다. 이 검사는 음성 유무를 구분하지 않으므로, 내레이션 영상의 소리 없는 정지 구간도 직접 확인해 5초를 넘지 않는지 검수한다.
     - 기본 noise 0.0005. 커서 이동·타이핑 같은 작은 변화는 noise가 크면 "정지"로, 너무 작으면(0.0002 이하) 인코딩 잡음이 "움직임"으로 판정된다. 애매하면 0.0003과 0.001로 돌려 보고, 의심 구간은 프레임을 뽑아 눈으로 확인한다. 스피너·깜빡이는 커서가 있는 화면도 눈으로 확인.
8. **음성 설명(내레이션)을 입힌다 — 요청이 있거나 보고 대상이 영상만 볼 사람일 때.** 캡션(`.srt`)을 Supertonic 3 한국어 음성으로 만들어 큐 시각에 맞춰 mp4에 합친다. [references/narration.md](references/narration.md)
   - 먼저 `node scripts/narrate.mjs 영상.mp4 --plan`: 합성만 하고 큐별 **음성 길이 vs 장면 길이**를 표로 낸다. 음성이 장면보다 길면(초과) 캡션을 줄이거나 그 장면의 `hold`를 늘려 다시 찍는다. 밀림(드리프트)이 2초를 넘는 큐도 같은 처리.
   - 음성 합성은 홈의 `Supertonic/.venv/bin/python`(supertonic-tts 스킬의 기본 설치 위치)을 쓴다. 다른 곳에 설치했으면 `SUPERTONIC_PYTHON` 환경 변수로 지정한다. 찾지 못하면 원인을 출력하고 실패한다.
   - 통과하면 `node scripts/narrate.mjs 영상.mp4` → `영상-narrated.mp4`. 영상 트랙은 복사된다. 정지 검사는 30초 기준(`check-freeze.sh 영상.mp4 30`)으로 다시 돌리고, 소리 없는 정지 구간은 5초 기준으로 직접 확인한다.
   - 캡션은 **읽히는 문장**으로 쓴다. URL·경로·해시·기호가 많은 캡션은 화면용 `.srt`와 별도로 읽기용 `.srt`(큐 시각 동일)를 만들어 `--srt`로 넘긴다. 자주 쓰는 기호(`→ · ≤ + % px` 등)는 `tts-batch.py`의 `SPOKEN` 표가 말로 바꾸고, 모델이 거부하는 문자는 지우고 다시 합성한다.
   - 합성은 큐당 수 초가 걸린다(58큐 ≈ 8분). 결과는 `출력 폴더/.narration/`에 캐시되어 같은 문장은 다시 만들지 않는다.
   - 보고서에는 내레이션 본을 주 영상으로 넣는다. 소리 없이 볼 사람을 위해 캡션은 영상에 그대로 남기고, 그래서 `<track>` 자막은 달지 않는다.
9. **보고서 폴더에 담는다.** 영상을 OS 동영상 폴더에 따로 두지 않고 **보고서와 같은 폴더**에 둔다.
   - 보고서는 파일 하나보다 **폴더**로 만드는 편이 낫다. 사용자에게도 그렇게 조언한다. 폴더와 보고서 파일 이름은 `YYYY-MM-DD {주제 혹은 이슈번호}`(날짜 + 공백 + 주제): `YYYY-MM-DD {주제}/` 안에 `YYYY-MM-DD {주제}.html`, `videos/`, 증거 파일. 자세한 이름 규칙은 `html-work-report` 스킬.
   - 보고서는 **HTML**로 쓰고 영상을 `<video controls>`로 embed한다(상대 경로, 구간 시작 시각을 함께 적는다).
   - 폴더 위치는 프로젝트의 문서 관례를 따른다. 관례가 없으면 사용자에게 묻는다.
   - 여러 클립은 `scripts/concat-clips.sh 출력.mp4 클립...`(코덱·해상도·fps가 다르면 중단, 구간 시작 시각 출력).
   - 자세히: [references/report.md](references/report.md). 보고서 본문 구성과 템플릿은 **`html-work-report` 스킬**(`assets/report-template.html`, 브라우저 검사 `scripts/check-report.mjs`)을 쓴다.
10. **정리하고 보고한다.** 서버 종료·포트 확인, DB 원복 확인, 워크트리 상태 확인. 보고: 보고서 경로, 영상 길이·구간 시작 시각, 상태별 비교표, 증거 파일 경로, **직접 확인한 것과 추정의 구분**, 예상과 달랐던 점.
11. **같은 실패가 5회 반복되면 멈춘다.** 원복·서버 종료 후 실패 보고서를 쓴다.

## 프레젠테이션 영상

보고서를 다 쓴 뒤, 검토자가 보고서를 열기 전에 보는 요약 영상을 만든다. 장면을 30초까지 멈추므로 내레이션이 필수다. 새 화면을 찍지 않고 **완성된 HTML 보고서를 절별로 스크롤**하며 캡션(=내레이션 대본)을 붙인다.

1. `scenes.json`을 쓴다. 장면마다 `{"target": "CSS 선택자", "caption": "1~2문장", "hold": 밀리초, "open": true(접힌 절을 열 때)}`. 순서는 요구사항(`#requirements`) → 검토 안내(`#review-guide`) → 완료 기준(`#criteria`) → 영상·핵심 구현 → 남은 위험(`#risks`)을 기본으로 하고, 무엇을 만들었는지와 위험도, 검토자 확인 지점을 반드시 말한다. 보고서에 없는 내용은 말하지 않는다.
2. `node scripts/present-report.mjs "<보고서>.html" scenes.json "<보고서폴더>/videos/presentation.mp4"` — 녹화 전에 선택자와 `hold`(30초 이하)를 검사한다.
3. 위 절차 8과 같이 `narrate.mjs --plan` → `narrate.mjs`로 음성을 입혀 `presentation-narrated.mp4`를 만든다. 음성이 장면보다 길면 `hold`를 늘려 다시 찍는다.
4. 정지 검사는 30초 기준. 보고서의 머리말 링크를 채우고 `check-report.mjs`를 다시 돌린다.

| `rec-lib.mjs` | 녹화 세션, 커서, 캡션(기본은 화면 밖 띠, 색은 보고서 템플릿과 같음, Pretendard가 있으면 사용), 강조, 설명/표 패널, 사람 속도 조작, 응답 저장, mp4·자막 저장 |

| `present-report.mjs` | HTML 보고서를 `scenes.json` 순서로 스크롤하며 캡션을 붙여 프레젠테이션 영상으로 녹화 |
| `check-freeze.sh` | 정지 구간 검사(통과 0 / 초과 1 / 읽기 실패 2) |
| `extract-frames.sh` | 검수용 프레임 추출 |
| `concat-clips.sh` | 클립 이어 붙이기(옆의 `.srt`는 `merge-captions.mjs`로 시각을 밀어 합침) |
| `merge-captions.mjs` | 클립별 `.srt`를 누적 길이만큼 밀어 `.srt`·`.vtt`로 합침 |
| `narrate.mjs` | `.srt` 큐를 Supertonic 음성으로 합성해 큐 시각에 맞춰 mp4에 입힘. `--plan`은 큐별 음성 길이·여유·밀림 표만 |
| `tts-batch.py` | `narrate.mjs`가 호출. Supertonic 모델을 한 번 로드해 여러 큐를 WAV로(기호 정규화, 미지원 문자 제거 재시도, 캐시). `~/Supertonic/.venv/bin/python`로 실행 |
