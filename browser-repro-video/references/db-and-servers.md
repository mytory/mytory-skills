# 재현 환경과 DB 원복 상세

## 상태별 서버
- 상태마다 git worktree를 만들고(`git worktree add ../repro-before <커밋>`) 서버를 포트를 나눠 띄운다. 같은 DB, 같은 프론트 빌드를 쓴다.
- 프론트 빌드 없이 띄우면 화면이 깨진다. 캡처 전에 스타일이 적용됐는지 첫 프레임으로 확인한다.
- 외부 서비스 응답이 필요하면 목으로 대체하되, 프로젝트의 원본 목·설정 파일은 고치지 않는다. 별도 파일을 만들어 실행 인자나 환경 변수로 지정한다.
- 서버 시작 스크립트는 실패 시 로그 위치를 출력하게 하고, 종료 스크립트(포트로 PID 찾아 kill)를 같이 만든다.

## DB를 바꾸는 재현 (허락을 기다리지 않고 진행, 원복은 필수)
1. 시작 전에 대상 행과 관련 테이블의 최대 id·행 수를 파일로 저장한다(기준값).
2. **원복 스크립트를 먼저 만든다.** 기준값과 비교해 같은지 출력까지 해야 완성이다.
   - UPDATE/DELETE는 대상 id를 WHERE로 명시한다. 조건 없는 쓰기 금지.
   - 저장이 비동기로 만드는 부수 행(이력·스냅샷·로그)도 원복 대상이다. 저장 직후 몇 초 뒤에 생기는 것도 있으니 원복 전에 잠시 기다린다.
   - 시퀀스는 되돌리지 않아도 되지만, 되돌리지 않았다는 사실을 보고에 적는다.
3. 상태 사이마다, 그리고 끝낼 때(실패로 중단할 때도: trap/finally) 원복하고 기준값과 비교한다.
4. 다시 찍기 전에도 원복부터.

## 증거 파일 이름 예
`request-<상태>.json`, `response-<상태>.json`, `db-before-<상태>.json`, `db-after-<상태>.json`, `result-<상태>.png`.
