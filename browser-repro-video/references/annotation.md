# 주석(설명) 만드는 법

## 원칙
- 캡션·패널·테두리 색은 **실제 응답·DB 조회 결과에서 계산한다.** 정답 기준값만 상수로 둔다.
- 판정 기준이 여럿이면 기준별로 따로 판정해 따로 표시한다.
  나쁜 예: 한 기준(등록 표시)만 보고 "맞음"을 붙였는데 캡션은 다른 기준(방향 표기)의 오류를 설명 → 어긋나서 재녹화.
  좋은 예: `1번 줄 | 등록 표시 ✓ | 방향 표기 ✗`
- 화면에서 구분이 안 되는 항목은 원래 값이 무엇인지 주석에 적는다(예: 화면엔 같게 보이지만 DB에는 `NULL`).
- **캡션의 숫자·목록은 화면에 보이는 것(뷰포트 안의 보이는 요소)을 기준으로 센다.** 응답 데이터나 일부만 센다면 기준을 캡션에 적는다(예: "웹콘솔 응답 기준 노드 7개", "이번 변경 대상 탭 3개(전체 5개)"). 실제 사례: 지도 노드 수를 웹소켓 응답에서 세어 화면과 달랐고, 탭 수를 변경 대상만 세어 전체 탭 수와 달랐다.
- 결론 문장도 결과에서 만든다. 예상과 다르게 나왔으면 "예상과 다름"으로 찍는다. 맞추려고 조작을 바꾸지 않는다.

## 배치
- 캡션·패널은 기본이 **화면 밖 띠**(위 캡션 띠, 아래 패널 띠)다. 화면을 가리지 않으므로 위치 고민이 없다. `overlay: true`일 때만 아래 규칙을 지킨다: 반투명 + 대상과 겹치지 않는 자리 + 프레임 확인.
- 구간 시작 캡션: (overlay일 때) 화면 위 전체 폭. `수정 전 (master)` / `수정 후 (브랜치명)` + 한 줄 설명.
- 설명 패널: 표 아래 등 **앱 화면의 핵심을 가리지 않는 위치**. 읽을 양이 많으면 패널을 둘로 나눠 차례로 보여 준다.
- overlay: 페이지 이동(goto)하면 캡션 배너·패널이 사라진다. `reapplyCaption`으로 다시 그린다. 띠 모드: 캡션은 유지되고 패널은 닫힌다.

## 읽기 시간
- 글자 수 기준으로 3~5초. 5초가 넘을 것 같으면 글을 줄이거나 화면을 나눈다(대기를 늘리지 않는다). `holdToRead`는 5초 초과 시 예외를 던진다.
