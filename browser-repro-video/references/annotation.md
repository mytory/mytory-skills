# 주석(설명) 만드는 법

## 원칙
- 캡션·패널·테두리 색은 **실제 응답·DB 조회 결과에서 계산한다.** 정답 기준값만 상수로 둔다.
- 판정 기준이 여럿이면 기준별로 따로 판정해 따로 표시한다.
  나쁜 예: 한 기준(등록 표시)만 보고 "맞음"을 붙였는데 캡션은 다른 기준(방향 표기)의 오류를 설명 → 어긋나서 재녹화.
  좋은 예: `1번 줄 | 등록 표시 ✓ | 방향 표기 ✗`
- 화면에서 구분이 안 되는 항목은 원래 값이 무엇인지 주석에 적는다(예: 화면엔 같게 보이지만 DB에는 `NULL`).
- 결론 문장도 결과에서 만든다. 예상과 다르게 나왔으면 "예상과 다름"으로 찍는다. 맞추려고 조작을 바꾸지 않는다.

## 배치
- 구간 시작 캡션: 화면 위 전체 폭. `수정 전 (master)` / `수정 후 (브랜치명)` + 한 줄 설명.
- 설명 패널: 표 아래 등 **앱 화면의 핵심을 가리지 않는 위치**. 읽을 양이 많으면 패널을 둘로 나눠 차례로 보여 준다.
- 페이지 이동(goto)하면 캡션 배너·패널이 사라진다. `reapplyCaption`으로 다시 그린다.

## 읽기 시간
- 글자 수 기준으로 3~5초. 5초가 넘을 것 같으면 글을 줄이거나 화면을 나눈다(대기를 늘리지 않는다). `holdToRead`는 5초 초과 시 예외를 던진다.
