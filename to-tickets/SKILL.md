# 티켓으로 나누기

계획, 명세 또는 대화를 **티켓**으로 나눕니다. 각 티켓은 기능을 끝까지 잇는 수직 슬라이스이며, 작업 시작을 막는 선행 티켓을 명시합니다.

이슈 트래커와 분류 라벨 설정이 없다면 사용자에게 `/setup-matt-pocock-skills`를 실행하도록 안내합니다.

## 절차

### 1. 맥락 수집

현재 대화에 있는 내용을 사용합니다. 사용자가 명세 경로나 이슈 번호·URL을 전달했다면 전체 본문과 댓글을 가져와 읽습니다.

### 2. 코드베이스 탐색(선택)

아직 살펴보지 않았다면 현재 코드 상태를 파악합니다. 티켓 제목과 설명에는 프로젝트 용어집의 도메인 용어를 사용하고 해당 영역의 ADR을 따릅니다. 구현이 쉬워지도록 코드를 먼저 정리할 기회도 찾습니다. "변경을 쉽게 만든 뒤 쉽게 변경한다."

### 3. 수직 슬라이스 초안

작업을 **탐색용 한 걸음(tracer bullet)**인 티켓으로 나눕니다.

- 각 슬라이스는 스키마, API, UI, 테스트 등 필요한 모든 계층을 좁지만 **완전하게** 관통합니다. 한 계층만 다루는 수평 슬라이스를 만들지 않습니다.
- 완료된 슬라이스는 그 자체로 시연하거나 검증할 수 있어야 합니다.
- 각 슬라이스는 새로운 컨텍스트 창 하나에서 끝낼 크기로 만듭니다.
- 사전 코드 정리가 필요하면 먼저 진행합니다.

각 티켓에 시작 전에 끝나야 하는 **차단 티켓**을 명시합니다. 차단 티켓이 없으면 즉시 시작할 수 있습니다.

**넓은 리팩터링은 수직 분할의 예외입니다.** 열 이름 변경이나 공유 심볼의 타입 변경처럼 한 기계적 수정이 코드베이스 전체에 퍼져 단일 슬라이스로는 정상 상태를 유지할 수 없는 경우, **확장 → 전환 → 축소** 순서로 나눕니다. 먼저 새 형태를 옛 형태와 함께 추가합니다. 그다음 패키지나 디렉터리 단위 등 변경 범위에 맞춰 호출부를 여러 티켓에서 전환합니다. 옛 형태를 유지해 각 배치의 CI가 통과하도록 합니다. 모든 전환이 끝난 뒤 차단 관계가 걸린 마지막 티켓에서 옛 형태를 삭제합니다. 배치별로도 정상 상태를 유지할 수 없다면 통합 브랜치를 공유하고 마지막 통합·검증 티켓에서만 정상 상태를 보장합니다.

### 4. 사용자에게 확인

제안한 티켓을 번호 목록으로 제시합니다. 각 티켓에 짧은 **제목**, 선행 **차단 티켓**, 완성되는 **전체 동작**을 적습니다.

작업 크기가 적절한지, 차단 관계가 실제로 필요한지, 합치거나 더 나눌 티켓이 있는지 묻고 승인받을 때까지 조정합니다.

### 5. 설정된 트래커에 게시

승인된 티켓을 게시합니다. 트래커 종류에 따라 차단 관계 표현만 달라집니다.

- **로컬 파일**: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`에 티켓 하나당 파일 하나를 씁니다. 선행 티켓부터 `01`로 번호를 붙이고 차단 티켓의 번호와 제목을 적습니다. 여러 티켓을 한 파일에 합치지 않습니다.
- **실제 이슈 트래커(GitHub, Linear 등)**: 선행 티켓부터 이슈 하나씩 게시합니다. 가능하면 플랫폼의 차단 관계 기능을 쓰고, 없으면 "Blocked by"에 이슈를 참조합니다. 원본이 기존 이슈였다면 각 티켓을 하위 이슈로 만듭니다. 별도 지시가 없다면 `ready-for-agent` 라벨을 붙입니다.

차단 티켓이 모두 완료된 티켓부터 작업합니다. 선형 관계라면 위에서 아래 순서입니다. 부모 이슈는 닫거나 수정하지 않습니다.

로컬 파일 양식:

```markdown
# <NN>: <티켓 제목>

**만들 것:** 계층별 구현 목록이 아닌 사용자 관점의 전체 동작.

**차단 티켓:** 선행 티켓 번호와 제목, 또는 "없음 (즉시 시작 가능)".

**상태:** ready-for-agent

- [ ] 인수 기준 1
- [ ] 인수 기준 2
```

이슈 트래커 양식:

```markdown
## 부모 이슈

원본이 기존 이슈였다면 부모 이슈 참조. 아니면 이 절을 생략.

## 만들 것

계층별 구현 목록이 아닌 사용자 관점의 전체 동작.

## 인수 기준

- [ ] 기준 1
- [ ] 기준 2

## 차단 티켓

차단 티켓 참조. 없으면 "없음 (즉시 시작 가능)". 플랫폼의 차단 관계를 설정했다면 이 절 생략.
```

두 형식 모두 쉽게 낡는 구체적 파일 경로나 코드 조각은 피합니다. 단, 프로토타입에서 나온 상태 머신, 리듀서, 스키마, 타입 형태 등이 설계 결정을 글보다 정확히 표현한다면 핵심 부분만 넣고 프로토타입에서 가져왔음을 밝힙니다. 실행 가능한 데모 전체는 넣지 않습니다.
