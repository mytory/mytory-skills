# 스킬 최신화

현재 저장소의 `AGENTS.md`와 `README.md`를 먼저 읽으세요. 이 스킬은 이 저장소에서만 실행하며, 다른 저장소에 설치했을 때는 해당 저장소의 출처 목록과 규칙이 있는지 확인한 뒤 적용하세요.

## 1. 대상과 기준 확정

1. `README.md`의 출처 표에서 외부 출처 스킬을 찾습니다. 자체 제작 스킬은 원본이 따로 명시된 경우에만 대상으로 삼습니다.
2. 각 원본 저장소의 최신 기본 브랜치 커밋을 확인하고, 로컬 스킬과 원본 스킬의 대응 경로를 조사합니다. 이름·구조가 바뀌면 기능과 참조 관계를 확인합니다.
3. `LAST_RUN.md`의 이전 결과와 현재 작업 트리를 확인합니다. 이미 있는 사용자 변경을 보존하고, 지난번 기준 SHA와 같으면 불필요한 수정을 하지 않습니다.

완료 기준: 대상 스킬별 원본 URL·커밋·대응 경로와 실제 변경 여부를 알 수 있습니다.

## 2. 갱신과 번역

1. 변경된 `SKILL.md`와 필요한 스크립트·설정·참고 자료·라이선스를 반영합니다. 기존 로컬 확장이 있으면 원본 변경과 대조해 기능을 보존합니다.
2. 설명과 지침을 한국어로 번역합니다. `name`, `/명령어`, CLI 명령, 파일 경로, 코드 식별자, 원본의 `license`·`metadata` 값은 유지합니다. `description`은 한국어 요청에 정확히 반응하도록 작성합니다.
3. 스킬 이름이 바뀌거나 새 의존 스킬이 생겼다면 호출 경로를 확인합니다. 기존 스킬을 삭제해야 할지 불명확하면 보존하고 결과에 이유를 적습니다.
4. `README.md`의 목록, 전체 개수, 출처와 기준 커밋, 이름 변경 안내를 실제 파일 구성과 맞춥니다.

완료 기준: 모든 반영 파일이 최신 원본의 해당 절차를 담고, 기존 로컬 기능과 영어 호출 이름이 유지됩니다.

## 3. 검증과 최신 기록

1. `SKILL.md` 프론트매터와 `agents/openai.yaml`을 파싱하고, `name`이 디렉터리 이름과 일치하는지 확인합니다.
2. README 링크·상대 링크·스크립트 구문과 관련 스모크 테스트를 확인합니다. `git diff --check`를 실행합니다.
3. 공개 저장소에 넣을 파일 전체에서 개인정보·인증 정보·내부 주소를 확인합니다. 파일 내용 검사와 Git 작성자 메타데이터 검사는 구분해 보고합니다.
4. 성공·부분 실패·변경 없음 중 실제 결과와 오늘 날짜를 `LAST_RUN.md`의 **마지막 처리일**로 덮어씁니다. 실패해도 처리일을 기록하고 이유를 적습니다. 과거 수행 항목과 다음 점검일은 남기지 않습니다.
5. 변경 내용, 검증 결과, 갱신하지 못한 출처를 사용자에게 간결하게 알립니다. 보고서가 필요하면 저장소의 `html-work-report` 지침을 따릅니다.

완료 기준: 결과 파일은 최신 수행 결과 한 건과 마지막 처리일만 담고, 이번 달 실행 여부를 판단할 수 있습니다.
