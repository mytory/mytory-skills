# 스킬 작성

## 절차

1. **요구사항 수집** - 사용자에게 물어보세요:
   - 이 스킬이 다루는 작업/도메인은?
   - 처리해야 할 구체적 사용 사례는?
   - 실행 가능한 스크립트가 필요한가, 아니면 지침만 필요한가?
   - 포함할 참고 자료가 있는가?

2. **스킬 초안 작성** - 생성:
   - 간결한 지침이 담긴 SKILL.md
   - 콘텐츠가 500줄을 초과하면 추가 참조 파일
   - 결정론적 작업이 필요하면 유틸리티 스크립트

3. **사용자와 검토** - 초안 제시 후 물어보기:
   - 사용 사례를 다루고 있는가?
   - 빠졌거나 불분명한 점이 있는가?
   - 더/덜 상세해야 할 섹션이 있는가?

## 스킬 구조

```
skill-name/
├── SKILL.md           # 주요 지침 (필수)
├── REFERENCE.md       # 상세 문서 (필요시)
├── EXAMPLES.md        # 사용 예시 (필요시)
└── scripts/           # 유틸리티 스크립트 (필요시)
    └── helper.js
```

## SKILL.md 템플릿

```md
---
name: skill-name
description: 기능에 대한 간략한 설명. [구체적인 트리거 조건]일 때 사용합니다.
---

# 스킬 이름

## 빠른 시작

[최소한의 작동 예시]

## 작업 흐름

[복잡한 작업을 위한 체크리스트가 있는 단계별 프로세스]

## 고급 기능

[별도 파일로 연결: [REFERENCE.md](REFERENCE.md) 참조]
```

## description 요구사항

description은 에이전트가 어떤 스킬을 로드할지 결정할 때 **보는 유일한 정보**입니다. 설치된 다른 모든 스킬과 함께 시스템 프롬프트에 표시됩니다. 에이전트는 이 description을 읽고 사용자 요청에 따라 관련 스킬을 선택합니다.

**목표**: 에이전트가 알 수 있을 만큼 충분한 정보 제공:

1. 이 스킬이 제공하는 기능
2. 언제/왜 트리거할지 (구체적 키워드, 맥락, 파일 유형)

**형식**:

- 최대 1024자
- 3인칭으로 작성
- 첫 문장: 하는 일
- 두 번째 문장: "[구체적 트리거 조건]일 때 사용합니다"

**좋은 예시**:

```
PDF 파일에서 텍스트와 표를 추출하고, 양식을 채우며, 문서를 병합합니다. PDF 파일 관련 작업 시 또는 사용자가 PDF, 양식, 문서 추출을 언급할 때 사용합니다.
```

**나쁜 예시**:

```
문서 작업을 도와줍니다.
```

나쁜 예시는 에이전트가 이 스킬을 다른 문서 스킬과 구별할 방법이 없습니다.

## 스크립트 추가 시기

유틸리티 스크립트 추가 시기:

- 작업이 결정론적일 때 (검증, 포맷팅)
- 같은 코드가 반복적으로 생성될 때
- 오류에 명시적 처리가 필요할 때

스크립트는 생성 코드 대비 토큰을 절약하고 신뢰성을 향상시킵니다.

## 파일 분할 시기

다음 경우에 별도 파일로 분할:

- SKILL.md가 100줄 초과
- 콘텐츠에 뚜렷한 도메인이 있음 (금융 vs 판매 스키마)
- 고급 기능이 드물게 필요함

## 검토 체크리스트

초안 작성 후 확인:

- [ ] description에 트리거 조건 포함 ("...할 때 사용합니다")
- [ ] SKILL.md 100줄 미만
- [ ] 시간에 민감한 정보 없음
- [ ] 일관된 용어
- [ ] 구체적인 예시 포함
- [ ] 참조는 한 단계 깊이
