# 분류

프로젝트 이슈 트래커의 이슈를 작은 분류 역할 상태 머신을 통해 이동시키세요.

분류 중에 이슈 트래커에 게시되는 모든 코멘트나 이슈는 **반드시** 이 면책문으로 시작해야 합니다:

```
> *이것은 분류 중에 AI에 의해 생성되었습니다.*
```

## 참조 문서

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 내구성 있는 에이전트 브리프 작성 방법
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 지식 베이스 작동 방식

## 역할

두 가지 **카테고리** 역할:

- `bug` — 무언가 고장 남
- `enhancement` — 새 기능 또는 개선

다섯 가지 **상태** 역할:

- `needs-triage` — 메인테이너가 평가 필요
- `needs-info` — 보고자의 추가 정보 대기 중
- `ready-for-agent` — 완전히 명세화됨, AFK 에이전트 대응 가능
- `ready-for-human` — 사람 구현 필요
- `wontfix` — 조치되지 않을 것

모든 분류된 이슈는 정확히 하나의 카테고리 역할과 하나의 상태 역할을 가져야 합니다. 상태 역할이 충돌하면 지적하고 다른 작업 전에 메인테이너에게 물어보세요.

이것들은 공식 역할 이름입니다 — 이슈 트래커에서 사용되는 실제 라벨 문자열은 다를 수 있습니다. 매핑이 제공되어 있어야 합니다 — 없으면 `/setup-matt-pocock-skills`를 실행하세요.

상태 전환: 라벨 없는 이슈는 보통 먼저 `needs-triage`로 이동; 거기서 `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`로 이동. `needs-info`는 보고자가 답변하면 `needs-triage`로 돌아감. 메인테이너는 언제든지 재정의 가능 — 비정상적으로 보이는 전환은 지적하고 진행 전에 물어보기.

## 호출

메인테이너가 `/triage`를 호출하고 자연어로 원하는 것을 설명합니다. 요청을 해석하고 행동하세요. 예시:

- "내 주의가 필요한 것 보여줘"
- "#42를 살펴보자"
- "#42를 ready-for-agent로 이동"
- "에이전트가 가져갈 준비된 것 뭐 있어?"

## 주의가 필요한 것 보여주기

이슈 트래커를 쿼리하고 세 버킷을, 오래된 것부터 제시:

1. **라벨 없음** — 분류된 적 없음.
2. **`needs-triage`** — 평가 진행 중.
3. **마지막 분류 노트 이후 보고자 활동이 있는 `needs-info`** — 재평가 필요.

개수와 이슈당 한 줄 요약 보여주기. 메인테이너가 선택하게 하세요.

## 특정 이슈 분류

1. **컨텍스트 수집.** 전체 이슈 읽기(본문, 코멘트, 라벨, 보고자, 날짜). 해결된 질문을 다시 묻지 않도록 이전 분류 노트 파싱. 프로젝트의 도메인 용어집을 사용해 코드베이스 탐색, 해당 영역의 ADR 존중. `.out-of-scope/*.md` 읽고 이 이슈와 유사한 이전 거부 표면화.

2. **권장.** 추론과 함께 카테고리와 상태 권장사항, 이슈와 관련된 간략한 코드베이스 요약을 메인테이너에게 알리기. 지시 대기.

3. **재현 (버그만).** 질문 전에 재현 시도: 보고자의 단계 읽기, 관련 코드 추적, 테스트나 명령 실행. 발생한 일 보고 — 코드 경로와 함께 성공적 재현, 실패한 재현, 또는 불충분한 세부사항(강력한 `needs-info` 신호). 확인된 재현은 훨씬 더 강력한 에이전트 브리프를 만듦.

4. **질문 (필요시).** 이슈가 더 구체화되어야 하면 `/grill-with-docs` 세션 실행.

5. **결과 적용:**
   - `ready-for-agent` — 에이전트 브리프 코멘트 게시 ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human` — 에이전트 브리프와 동일한 구조지만, 위임할 수 없는 이유 기록 (판단 필요, 외부 접근, 디자인 결정, 수동 테스트).
   - `needs-info` — 분류 노트 게시 (아래 템플릿).
   - `wontfix` (버그) — 정중한 설명 후 닫기.
   - `wontfix` (기능 개선) — `.out-of-scope/`에 작성, 코멘트에서 링크, 그 후 닫기 ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `needs-triage` — 역할 적용. 부분 진행이 있으면 선택적 코멘트.

## 빠른 상태 재정의

메인테이너가 "#42를 ready-for-agent로 이동"이라고 말하면, 신뢰하고 직접 역할 적용. 수행할 작업 확인(역할 변경, 코멘트, 닫기) 후 실행. 질문 건너뛰기. 질문 세션 없이 `ready-for-agent`로 이동 시, 에이전트 브리프를 작성할지 물어보기.

## Needs-info 템플릿

```markdown
## 분류 노트

**지금까지 확립된 것:**

- 포인트 1
- 포인트 2

**@보고자님께 아직 필요한 것:**

- 질문 1
- 질문 2
```

질문 중 해결된 모든 것을 "지금까지 확립된 것" 아래에 캡처하여 작업이 손실되지 않게 하기. 질문은 "더 많은 정보를 제공해 주세요"가 아닌 구체적이고 실행 가능해야 함.

## 이전 세션 재개

이슈에 이전 분류 노트가 있으면 읽고, 보고자가 남은 질문에 답변했는지 확인하고, 계속하기 전에 업데이트된 상황 제시. 해결된 질문을 다시 묻지 않기.
