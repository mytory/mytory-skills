# 범위 외 지식 베이스

저장소의 `.out-of-scope/` 디렉터리는 거부된 기능 요청의 영구 기록을 저장합니다. 두 가지 목적:

1. **제도적 기억** — 기능이 거부된 이유, 이슈가 닫힐 때 추론이 손실되지 않도록
2. **중복 제거** — 이전 거부와 일치하는 새 이슈가 들어오면, 스킬이 재논의 대신 이전 결정을 표면화

## 디렉터리 구조

```
.out-of-scope/
├── dark-mode.md
├── plugin-system.md
└── graphql-api.md
```

이슈당이 아닌 **개념**당 하나의 파일. 같은 것을 요청하는 여러 이슈는 하나의 파일로 그룹화.

## 파일 형식

파일은 느슨하고 읽기 쉬운 스타일로 작성 — 데이터베이스 항목보다 짧은 디자인 문서에 가깝게. 단락, 코드 샘플, 예시를 사용해 추론을 처음 접하는 사람에게도 명확하고 유용하게.

```markdown
# 다크 모드

이 프로젝트는 다크 모드나 사용자 대상 테마를 지원하지 않습니다.

## 범위 외인 이유

렌더링 파이프라인은 `ThemeConfig`에 정의된 단일 색상 팔레트를 가정합니다.
여러 테마 지원에는 다음이 필요:

- 전체 컴포넌트 트리를 감싸는 테마 컨텍스트 제공자
- 컴포넌트별 테마 인식 스타일 해석
- 사용자 테마 선호도를 위한 지속성 레이어

이는 프로젝트의 콘텐츠 저작 집중과 맞지 않는 중대한 아키텍처 변경입니다.
테마는 출력을 임베드하거나 재배포하는 하류 소비자의 관심사입니다.

```ts
// 현재 ThemeConfig 인터페이스는 런타임 전환을 위해 설계되지 않음:
interface ThemeConfig {
  colors: ColorPalette; // 단일 팔레트, 빌드 시점에 해석
  fonts: FontStack;
}
```

## 이전 요청

- #42 — "다크 모드 지원 추가"
- #87 — "접근성을 위한 야간 테마"
- #134 — "다크 테마 옵션"
```

### 파일 이름 짓기

개념에 대해 짧고 설명적인 kebab-case 이름 사용: `dark-mode.md`, `plugin-system.md`, `graphql-api.md`. 디렉터리를 브라우징하는 사람이 파일을 열지 않고도 무엇이 거부되었는지 이해할 수 있을 정도로 인식 가능해야 함.

### 이유 작성

이유는 실질적이어야 함 — "원하지 않아서"가 아니라 이유를 설명. 좋은 이유는 다음을 참조:

- 프로젝트 범위 또는 철학 ("이 프로젝트는 X에 집중; 테마는 하류 관심사")
- 기술적 제약 ("이것을 지원하려면 Y가 필요, 이는 Z 아키텍처와 충돌")
- 전략적 결정 ("B 대신 A를 사용하기로 선택한 이유는...")

이유는 내구성 있어야 함. 일시적 상황 참조 피하기 ("지금 너무 바빠서") — 진정한 거부가 아니라 연기.

## `.out-of-scope/` 확인 시기

분류 중 (1단계: 컨텍스트 수집), `.out-of-scope/`의 모든 파일 읽기. 새 이슈 평가 시:

- 요청이 기존 범위 외 개념과 일치하는지 확인
- 일치는 키워드가 아닌 개념 유사성으로 — "night theme"은 `dark-mode.md`와 일치
- 일치하면 메인테이너에게 표면화: "이것은 `.out-of-scope/dark-mode.md`와 유사 — [이유] 때문에 이전에 거부했습니다. 여전히 같은 생각이신가요?"

메인테이너가 할 수 있는 것:

- **확인** — 새 이슈는 기존 파일의 "이전 요청" 목록에 추가 후 닫힘
- **재고려** — 범위 외 파일이 삭제되거나 업데이트되고, 이슈는 정상 분류 진행
- **동의하지 않음** — 이슈는 관련 있지만 별개, 정상 분류 진행

## `.out-of-scope/`에 작성하는 시기

**기능 개선**(버그 아님)이 `wontfix`로 거부된 경우에만. 흐름:

1. 메인테이너가 기능 요청이 범위 외라고 결정
2. 일치하는 `.out-of-scope/` 파일이 이미 존재하는지 확인
3. 있으면: "이전 요청" 목록에 새 이슈 추가
4. 없으면: 개념명, 결정, 이유, 첫 번째 이전 요청으로 새 파일 생성
5. 결정을 설명하고 `.out-of-scope/` 파일을 언급하는 코멘트를 이슈에 게시
6. `wontfix` 라벨로 이슈 닫기

## 범위 외 파일 업데이트 또는 제거

메인테이너가 이전에 거부된 개념에 대해 마음을 바꾸면:

- `.out-of-scope/` 파일 삭제
- 스킬이 오래된 이슈를 다시 열 필요 없음 — 역사적 기록
- 재고려를 촉발한 새 이슈는 정상 분류 진행
