# 리디자인 스킬

## 작동 방식

기존 프로젝트에 적용할 때 이 순서를 따르세요:

1. **스캔** — 코드베이스 읽기. 프레임워크, 스타일링 방식(Tailwind, 바닐라 CSS, styled-components 등), 현재 디자인 패턴 식별.
2. **진단** — 아래 감사 실행. 발견한 모든 일반적인 패턴, 취약점, 누락된 상태 나열.
3. **수정** — 기존 스택으로 작업하면서 대상화된 업그레이드 적용. 처음부터 다시 작성하지 않음. 있는 것을 개선.

## 디자인 감사

### 타이포그래피

다음 문제 확인 및 수정:

- **브라우저 기본 폰트 또는 Inter가 모든 곳에.** 개성 있는 폰트로 교체. 좋은 옵션: `Geist`, `Outfit`, `Cabinet Grotesk`, `Satoshi`. 에디토리얼/창의적 프로젝트의 경우, 세리프 헤더와 산세리프 본문 페어링.
- **헤드라인에 존재감 부족.** 디스플레이 텍스트 크기를 키우고, 자간을 좁히고, 행간을 줄이기. 헤드라인은 무겁고 의도적으로 느껴져야 함.
- **본문 텍스트 너무 넓음.** 단락 너비를 대략 65자로 제한. 가독성을 위해 행간 증가.
- **Regular (400)과 Bold (700) 굵기만 사용.** 더 미묘한 계층을 위해 Medium (500)과 SemiBold (600) 도입.
- **숫자가 비례 폰트로.** 데이터 밀집형 인터페이스에는 고정폭 폰트 사용 또는 표 형식 숫자 활성화 (`font-variant-numeric: tabular-nums`).
- **자간 조정 누락.** 큰 헤더에는 음수 트래킹, 작은 캡스나 레이블에는 양수 트래킹 사용.
- **모든 곳에 올캡스 서브헤더.** 대신 소문자 이탤릭, 문장형 대소문자, 스몰캡스 시도.
- **고아 단어.** 마지막 줄에 혼자 있는 단일 단어. `text-wrap: balance` 또는 `text-wrap: pretty`로 수정.

### 색상 및 표면

- **순수 `#000000` 배경.** 오프블랙, 다크 차콜, 틴트 다크 (`#0a0a0a`, `#121212`, 또는 다크 네이비)로 교체.
- **과채도 강조 색상.** 채도를 80% 미만으로 유지. 중립색과 혼합되도록 강조색 탈채도.
- **둘 이상의 강조 색상.** 하나만 선택. 나머지 제거. 일관성이 다양성보다 우선.
- **따뜻한 회색과 차가운 회색 혼합.** 한 회색 계열에 고수. 모든 회색에 일관된 색조(따뜻함 또는 차가움, 둘 다 안 됨)로 틴트.
- **보라/파랑 "AI 그라데이션" 미학.** 가장 흔한 AI 디자인 지문. 중립 베이스와 하나의 신중한 강조색으로 교체.
- **일반적인 `box-shadow`.** 배경 색조와 일치하도록 그림자 틴트. 순수 검정 저불투명도 대신 채색된 그림자 사용(예: 파란 배경에 짙은 파란 그림자).
- **텍스처가 전혀 없는 플랫 디자인.** 배경에 미묘한 노이즈, 그레인, 마이크로 패턴 추가. 순수 플랫 벡터는 무균적으로 느껴짐.
- **완벽하게 균일한 그라데이션.** 표준 선형 45도 페이드 대신 래디얼 그라데이션, 노이즈 오버레이, 메시 그라데이션으로 균일성 깨기.
- **일관되지 않은 조명 방향.** 모든 그림자를 감사하여 단일하고 일관된 광원을 제안하는지 확인.
- **라이트 모드 페이지의 무작위 다크 섹션 (또는 그 반대).** 라이트 페이지를 깨는 단일 다크 배경 섹션은 복사-붙여넣기 사고처럼 보임. 완전한 다크 모드에 전념하거나 전체에 일관된 배경 톤 유지. 대비가 필요하면 동일 팔레트의 약간 더 어두운 음영 사용 — 크림 페이지 중간에 갑자기 `#111`로 점프하지 않기.
- **시각적 깊이 없는 비어 있는 플랫 섹션.** 평범한 배경에 텍스트만 있는 섹션은 미완성처럼 느껴짐. 고품질 배경 이미지(블러, 오버레이, 마스크), 미묘한 패턴, 앰비언트 그라데이션 추가. 실제 에셋이 없을 때는 `https://picsum.photos/seed/{name}/1920/1080` 같은 신뢰할 수 있는 플레이스홀더 소스 사용. 히어로 섹션, 기능 블록, CTA 뒤에 배경 이미지 실험 — 낮은 불투명도의 미묘한 전체 너비 사진만으로도 존재감 추가.

### 레이아웃

- **모든 것이 중앙에 대칭.** 오프셋 마진, 혼합 종횡비, 중앙 콘텐츠 위의 왼쪽 정렬 헤더로 대칭 깨기.
- **기능 행으로서의 세 개의 동등한 카드 열.** 가장 일반적인 AI 레이아웃. 2열 지그재그, 비대칭 그리드, 수평 스크롤, 메이슨리 레이아웃으로 교체.
- **전체 화면 섹션에 `height: 100vh` 사용.** 모바일 브라우저(iOS Safari 뷰포트 버그)에서 레이아웃 점핑 방지를 위해 `min-height: 100dvh`로 교체.
- **복잡한 flexbox 백분율 계산.** 신뢰할 수 있는 다중 열 구조를 위해 CSS Grid로 교체.
- **max-width 컨테이너 없음.** 와이드 화면에서 콘텐츠가 가장자리에서 가장자리로 늘어나지 않도록 자동 마진이 있는 컨테이너 제약(약 1200-1440px) 추가.
- **flexbox로 강제된 동일 높이 카드.** 콘텐츠 길이에 따라 가변 높이 허용 또는 메이슨리 사용.
- **모든 것에 균일한 border-radius.** 반경 변화: 내부 요소는 더 좁게, 컨테이너는 더 부드럽게.
- **겹침이나 깊이 없음.** 요소가 서로 옆에 평평하게 위치. 네거티브 마진으로 레이어링과 시각적 깊이 생성.
- **대칭적 수직 패딩.** 상단과 하단 패딩이 항상 동일. 시각적으로 조정 — 하단 패딩은 종종 약간 더 커야 함.
- **대시보드에 항상 왼쪽 사이드바.** 대신 상단 내비게이션, 플로팅 명령 메뉴, 접을 수 있는 패널 시도.
- **화이트스페이스 부족.** 간격 두 배로. 디자인이 숨 쉬게 하기. 밀집된 레이아웃은 데이터 대시보드용이지 마케팅 페이지용이 아님.
- **카드 그룹에서 버튼이 하단 정렬되지 않음.** 카드의 콘텐츠 길이가 다르면 CTA가 무작위 높이에 위치. 위 콘텐츠와 관계없이 깔끔한 수평선을 형성하도록 각 카드 하단에 버튼 고정.
- **기능 목록이 다른 수직 위치에서 시작.** 가격 테이블이나 비교 카드에서, 기능 목록은 모든 열에서 동일한 Y 위치에서 시작해야 함. 목록 위에 일관된 간격 사용 또는 고정 높이 제목/가격 블록.
- **나란히 있는 요소의 일관되지 않은 수직 리듬.** 카드, 열, 패널을 나란히 배치할 때 공유 요소(제목, 설명, 가격, 버튼)를 모든 항목에 맞춰 정렬. 잘못 정렬된 기준선은 레이아웃이 깨진 것처럼 보이게 함.
- **시각적으로 틀려 보이는 수학적 정렬.** 수학으로 중앙 정렬이 항상 눈에 중앙으로 보이지 않음. 텍스트 옆 아이콘, 원 안의 재생 버튼, 버튼 안의 텍스트는 종종 올바르게 느껴지기 위해 1-2px 시각적 조정 필요.

### 인터랙티비티 및 상태

- **버튼에 호버 상태 없음.** 호버 시 배경 이동, 약간의 스케일, 이동 추가.
- **액티브/누름 피드백 없음.** 물리적 클릭 시뮬레이션을 위해 누름 시 미묘한 `scale(0.98)` 또는 `translateY(1px)` 추가.
- **지속 시간이 0인 즉각적인 트랜지션.** 모든 인터랙티브 요소에 부드러운 트랜지션(200-300ms) 추가.
- **포커스 링 누락.** 키보드 내비게이션을 위한 가시적 포커스 표시기 보장. 접근성 요구사항이며 선택 사항이 아님.
- **로딩 상태 없음.** 레이아웃 모양과 일치하는 스켈레톤 로더로 일반 원형 스피너 교체.
- **빈 상태 없음.** 아무것도 보여주지 않는 빈 대시보드는 기회 낭비. 구성된 "시작하기" 뷰 디자인.
- **오류 상태 없음.** 폼에 명확한 인라인 오류 메시지 추가. `window.alert()` 사용 금지.
- **죽은 링크.** `#`로 연결되는 버튼. 실제 목적지로 연결하거나 시각적으로 비활성화.
- **내비게이션에 현재 페이지 표시 없음.** 사용자가 어디에 있는지 알 수 있도록 활성 nav 링크를 다르게 스타일링.
- **스크롤 점핑.** 앵커 클릭이 즉시 점프. `scroll-behavior: smooth` 추가.
- **`top`, `left`, `width`, `height`를 사용하는 애니메이션.** GPU 가속 부드러운 애니메이션을 위해 `transform`과 `opacity`로 전환.

### 콘텐츠

- **"John Doe"나 "Jane Smith" 같은 일반 이름.** 다양하고 현실감 있는 이름 사용.
- **`99.99%`, `50%`, `$100.00` 같은 가짜 깔끔한 숫자.** 유기적이고 지저분한 데이터 사용: `47.2%`, `$99.00`, `+1 (312) 847-1928`.
- **"Acme Corp", "Nexus", "SmartFlow" 같은 플레이스홀더 회사명.** 맥락에 맞는 믿을 수 있는 브랜드명 발명.
- **AI 카피라이팅 클리셰.** "Elevate", "Seamless", "Unleash", "Next-Gen", "Game-changer", "Delve", "Tapestry", "In the world of..." 절대 사용 금지. 평이하고 구체적인 언어로 작성.
- **성공 메시지의 느낌표.** 제거. 자신감 있게, 시끄럽지 않게.
- **"이런!" 오류 메시지.** 직접적으로: "연결 실패. 다시 시도해 주세요."
- **수동태.** 능동태 사용: "실수가 있었습니다" 대신 "변경사항을 저장하지 못했습니다".
- **모든 블로그 게시물 날짜가 동일.** 실제처럼 보이도록 날짜 무작위화.
- **여러 사용자에 동일한 아바타 이미지.** 각 고유한 사람에게 고유 에셋 사용.
- **Lorem Ipsum.** 플레이스홀더 라틴 텍스트 절대 사용 금지. 실제 초안 카피 작성.
- **모든 헤더에 Title Case.** 대신 문장형 대소문자 사용.

### 컴포넌트 패턴

- **일반적인 카드 룩 (보더 + 그림자 + 흰색 배경).** 보더 제거, 또는 배경색만 사용, 또는 간격만 사용. 카드는 상승이 계층을 전달할 때만 존재해야 함.
- **항상 채워진 버튼 하나 + 고스트 버튼 하나.** 시각적 노이즈를 줄이기 위해 텍스트 링크나 3차 스타일 추가.
- **필 모양 "New" 및 "Beta" 배지.** 사각형 배지, 플래그, 일반 텍스트 레이블 시도.
- **아코디언 FAQ 섹션.** 나란히 배치된 목록, 검색 가능한 도움말, 인라인 점진적 공개로 교체.
- **점이 있는 3카드 캐러셀 추천사.** 메이슨리 월, 임베디드 소셜 게시물, 단일 회전 인용문으로 교체.
- **3개의 탑이 있는 가격 테이블.** 추가 높이뿐만 아니라 색상과 강조로 추천 티어 강조.
- **모든 것에 모달.** 간단한 액션에 팝업 대신 인라인 편집, 슬라이드 오버 패널, 확장 가능 섹션 사용.
- **아바타 원만 사용.** 덜 일반적인 룩을 위해 스퀴클이나 둥근 사각형 시도.
- **라이트/다크 토글은 항상 해/달 스위치.** 드롭다운, 시스템 기본 설정 감지, 설정에 통합 시도.
- **4열 푸터 링크 팜.** 단순화. 주요 내비게이션 경로와 법적으로 필수 링크에 집중.

### 아이코노그래피

- **Lucide 또는 Feather 아이콘만.** 기본 AI 아이콘 선택. 차별화를 위해 Phosphor, Heroicons, 맞춤 세트 사용.
- **"Launch"에는 로켓, "Security"에는 방패.** 덜 뻔한 아이콘으로 클리셰 메타포 교체(bolt, fingerprint, spark, vault).
- **아이콘 간 일관되지 않은 획 너비.** 모든 아이콘 감사하고 하나의 획 가중치로 표준화.
- **파비콘 누락.** 항상 브랜드 파비콘 포함.
- **스톡 "다양한 팀" 사진.** 불쾌한 스톡 이미지 대신 실제 팀 사진, 캔디드 샷, 일관된 일러스트레이션 스타일 사용.

### 코드 품질

- **Div 수프.** 시맨틱 HTML 사용: `<nav>`, `<main>`, `<article>`, `<aside>`, `<section>`.
- **CSS 클래스와 혼합된 인라인 스타일.** 모든 스타일링을 프로젝트의 스타일링 시스템으로 이동.
- **하드코딩된 픽셀 너비.** 유연한 레이아웃을 위해 상대 단위(`%`, `rem`, `em`, `max-width`) 사용.
- **이미지에 alt 텍스트 누락.** 의미 있는 이미지에 대체 텍스트 설명. 절대 `alt=""`나 `alt="image"` 방치 금지.
- **`9999` 같은 임의 z-index 값.** 테마/변수에 깔끔한 z-index 스케일 수립.
- **주석 처리된 죽은 코드.** 배포 전 모든 디버그 아티팩트 제거.
- **임포트 환각.** 모든 임포트가 실제로 `package.json` 또는 프로젝트 의존성에 존재하는지 확인.
- **메타 태그 누락.** 적절한 `<title>`, `description`, `og:image`, 소셜 공유 메타 태그 추가.

### 전략적 누락 (AI가 일반적으로 잊는 것)

- **법적 링크 없음.** 푸터에 개인정보처리방침 및 이용약관 링크 추가.
- **"뒤로" 내비게이션 없음.** 사용자 흐름의 막다른 골목. 모든 페이지에 돌아갈 방법 필요.
- **맞춤 404 페이지 없음.** 도움이 되고 브랜드화된 "페이지를 찾을 수 없음" 경험 디자인.
- **폼 유효성 검사 없음.** 이메일, 필수 필드, 형식 확인에 대한 클라이언트 측 유효성 검사 추가.
- **"콘텐츠로 건너뛰기" 링크 없음.** 키보드 사용자에게 필수. 숨겨진 스킵 링크 추가.
- **쿠키 동의 없음.** 관할권에서 요구하는 경우, 준수하는 동의 배너 추가.

## 업그레이드 기술

프로젝트 업그레이드 시, 일반 패턴을 교체하기 위해 이 고임팩트 기술에서 가져오세요:

### 타이포그래피 업그레이드
- **가변 폰트 애니메이션.** 스크롤 또는 호버 시 굵기나 너비 보간으로 살아있는 텍스트.
- **외곽선에서 채우기 트랜지션.** 텍스트가 획 외곽선으로 시작하여 스크롤 진입 또는 인터랙션 시 색상으로 채워짐.
- **텍스트 마스크 노출.** 뒤의 비디오나 애니메이션 이미지로의 창 역할을 하는 큰 타이포그래피.

### 레이아웃 업그레이드
- **깨진 그리드 / 비대칭.** 의도적으로 열 구조를 무시하는 요소 — 겹침, 화면 밖 블리딩, 계산된 무작위성으로 오프셋.
- **화이트스페이스 극대화.** 단일 요소에 포커스를 강제하는 화이트스페이스의 공격적 사용.
- **패럴랙스 카드 스택.** 스크롤 중에 서로 달라붙어 물리적으로 쌓이는 섹션.
- **분할 화면 스크롤.** 반대 방향으로 슬라이딩하는 두 개의 화면 절반.

### 모션 업그레이드
- **관성 있는 부드러운 스크롤.** 더 무겁고 시네마틱한 느낌을 위해 브라우저 기본값에서 스크롤 분리.
- **엇갈린 진입.** 요소가 약간의 지연으로 캐스케이드 진입, Y축 이동과 불투명도 페이드 결합. 모든 것을 한 번에 마운트하지 마세요.
- **스프링 물리.** 모든 인터랙티브 요소에 자연스럽고 무게감 있는 느낌을 위해 선형 이징을 스프링 기반 모션으로 교체.
- **스크롤 구동 노출.** 스크롤 진행에 연결된 확장 마스크, 와이프, 드로우온 SVG 경로를 통해 진입하는 콘텐츠.

### 표면 업그레이드
- **진정한 글래스모피즘.** `backdrop-filter: blur`를 넘어서기. 가장자리 굴절을 시뮬레이션하는 1px 내부 보더와 미묘한 내부 그림자 추가.
- **스포트라이트 보더.** 커서 아래에서 동적으로 빛나는 카드 보더.
- **그레인 및 노이즈 오버레이.** 디지털 평탄함을 깨기 위한 미묘한 노이즈가 있는 고정 `pointer-events-none` 오버레이.
- **채색된 틴트 그림자.** 일반 검정이 아닌 배경 색조를 전달하는 그림자.

## 수정 우선순위

최대 시각적 임팩트와 최소 위험을 위해 이 순서로 변경 적용:

1. **폰트 교체** — 가장 큰 즉각적 개선, 최저 위험
2. **색상 팔레트 정리** — 충돌하거나 과채도 색상 제거
3. **호버 및 활성 상태** — 인터페이스를 살아있게 만듦
4. **레이아웃 및 간격** — 적절한 그리드, max-width, 일관된 패딩
5. **일반 컴포넌트 교체** — 클리셰 패턴을 현대적 대안으로 교체
6. **로딩, 빈, 오류 상태 추가** — 완성된 느낌을 줌
7. **타이포그래피 스케일 및 간격 다듬기** — 프리미엄 최종 터치

## 규칙

- 기존 기술 스택으로 작업. 프레임워크나 스타일링 라이브러리 마이그레이션 금지.
- 기존 기능 깨지 않기. 모든 변경 후 테스트.
- 새 라이브러리 가져오기 전에 프로젝트의 의존성 파일 먼저 확인.
- 프로젝트가 Tailwind 사용 시, 설정 수정 전 버전(v3 vs v4) 확인.
- 프로젝트에 프레임워크가 없으면 바닐라 CSS 사용.
- 변경사항을 검토 가능하고 집중적으로 유지. 큰 재작성보다 작고 대상화된 개선.
