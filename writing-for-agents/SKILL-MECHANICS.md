# 스킬 작동 방식

[`writing-for-agents`](SKILL.md)의 스킬 전용 분기입니다. 문서가 스킬일 때 달라지는 프론트매터, 호출 방식, 라우터 스킬을 다룹니다. 나머지 작성 원칙은 `SKILL.md`의 공통 참고 자료를 따릅니다.

## 호출 방식

두 방식은 두 가지 부하 사이에서 선택합니다.

- **모델이 호출하는 스킬**에는 `description`이 있으므로 에이전트가 자율적으로 호출할 수 있고 다른 스킬도 참조할 수 있습니다. 사람이 이름을 직접 입력해 호출할 수도 있습니다. 모델 호출은 사람의 호출 가능성을 없애지 않고 발견 가능성을 더합니다. description은 항상 로드되는 최상위 컨텍스트 포인터이므로 발견 가능성의 대가로 지속적인 컨텍스트 부하를 씁니다. 내용이 전부 참고 자료라면 여러 스킬이 공유하는 참고 자료의 본거지가 될 수도 있습니다. 설정할 때는 `disable-model-invocation`을 생략하고, `SKILL.md`의 포인터 작성 규칙에 따라 각 발동 분기를 담은 모델용 description을 작성하세요.
- **사용자가 호출하는 스킬**은 description이 에이전트에게 노출되지 않습니다. 사람이 이름을 입력할 때만 호출할 수 있으며 다른 스킬은 호출할 수 없습니다. 컨텍스트 부하는 없지만 존재를 기억해야 하는 인지 부하가 생깁니다. 설정할 때는 `disable-model-invocation: true`를 넣고, description은 트리거 목록 없이 사람이 읽을 한 줄 요약으로 쓰세요.

에이전트가 스스로 사용해야 하거나 다른 스킬이 참조해야 할 때만 모델 호출을 선택하세요. 항상 사람이 직접 실행하는 스킬이라면 사용자 호출로 만들어 컨텍스트 부하를 없애세요.

사용자 호출 스킬 두 개가 같은 참고 자료를 필요로 한다면 어느 한 스킬 안에 두지 마세요. description이 없어 서로를 호출할 수 없습니다. 스킬 시스템 밖의 일반 파일에 두고 두 스킬에서 가리키세요.

## 호출 방식에 따라 나누기

순서에 따라 나누는 방법은 `SKILL.md`에 있습니다. 별도로 발동해야 하는 고유한 선도 단어가 있고 실제 프롬프트에서 그 단어를 사용하거나, 다른 스킬이 참조해야 한다면 모델 호출 스킬로 분리하세요. 항상 로드되는 새 description만큼 컨텍스트 부하가 늘어나므로 독립적인 접근이 그 비용을 정당화해야 합니다.

## 라우터 스킬

사용자 호출 스킬이 많아져 기억하기 어려우면 **라우터 스킬**을 만드세요. 다른 스킬의 이름과 각각을 사용해야 할 때를 알려 주는 사용자 호출 스킬입니다. 사람은 라우터 하나만 기억하면 됩니다. 라우터는 다른 스킬을 안내할 수만 있고 직접 호출할 수는 없습니다. 사용자 호출 스킬에는 에이전트에게 노출되는 description이 없어서 사람만 호출할 수 있기 때문입니다.
