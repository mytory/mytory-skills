# 도메인 문서

엔지니어링 스킬이 코드베이스 탐색 시 이 저장소의 도메인 문서를 소비하는 방법.

## 탐색 전에 읽어야 할 것

- 저장소 루트의 **`CONTEXT.md`**, 또는
- 존재하면 저장소 루트의 **`CONTEXT-MAP.md`** — 컨텍스트당 하나의 `CONTEXT.md`를 가리킴. 주제와 관련된 각각 읽기.
- **`docs/adr/`** — 작업할 영역을 다루는 ADR 읽기. 다중 컨텍스트 저장소에서는 컨텍스트 범위 결정을 위해 `src/<context>/docs/adr/`도 확인.

이 파일 중 하나라도 존재하지 않으면 **조용히 진행**. 부재를 지적하지 말고; 미리 생성하자고 제안하지 말 것. 생산자 스킬(`/grill-with-docs`)이 용어나 결정이 실제로 정리될 때 게으르게 생성.

## 파일 구조

단일 컨텍스트 저장소 (대부분의 저장소):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

다중 컨텍스트 저장소 (루트에 `CONTEXT-MAP.md` 존재):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 시스템 전역 결정
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 컨텍스트별 결정
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 용어집 어휘 사용

도메인 개념을 명명할 때(이슈 제목, 리팩터 제안, 가설, 테스트명), `CONTEXT.md`에 정의된 용어 사용. 용어집이 명시적으로 피하는 동의어로 이탈하지 말 것.

필요한 개념이 아직 용어집에 없으면, 신호 — 프로젝트가 사용하지 않는 언어를 만들어내고 있는 것(재고려)이거나 실제 간극이 있는 것(`/grill-with-docs`를 위해 기록).

## ADR 충돌 지적

출력이 기존 ADR과 모순되면 조용히 재정의하지 말고 명시적으로 표면화:

> _ADR-0007(이벤트 소싱 주문)과 모순 — 하지만 재논의 가치가 있음, 왜냐하면…_
