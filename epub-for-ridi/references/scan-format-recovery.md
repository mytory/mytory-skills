# 스캔 PDF에서 볼드·소제목·블록인용 복원

스캔본(이미지 PDF)을 OCR/추출한 텍스트 레이어는 **문자만** 준다. 원본의
굵게, 소제목, 블록인용 같은 서식은 사라진다. 이 문서는 "Strike!(John
McIlroy)" 한국어판 제작에서 실제로 쓴 방법과 함정을 기록한다.

전제: PDF에 검색 가능한 텍스트 레이어가 있어 단어 좌표를 얻을 수 있어야 한다.
순수 이미지(레이어 없음)면 OCR 단계에서 단어 bbox를 함께 남겨야 한다.

## 1. 볼드 검출 — 잉크 런(ink-run) 중앙값

텍스트 레이어에는 굵기 정보가 없다. 글리프 이름의 `Bold` 표기도 폰트에 따라
불안정하다. **렌더링 픽셀의 수평 획 두께**를 재는 편이 견고했다.

- 페이지를 400 dpi(회색조)로 렌더한다. 300 dpi도 시도 가능하나 실측에서
  400 dpi가 굵기 대비가 더 안정적이었다.
- 단어 bbox 안의 어두운 픽셀(<110)을 스캔해 **행(row)별 연속 수평 런**을 모은다.
- 런 길이의 **중앙값**을 그 단어의 굵기(`st`)로 삼는다.
- 페이지 단어들의 `st` 중앙값을 본문 기준선으로 두고
  `BOLD = max(body+1.6, body*1.28)` 이상이면 볼드로 판정한다.

실측(400 dpi): 본문 ~5px, 볼드 ~9px. DPI·폰트가 다르면 임계값도 달라지므로
반드시 그 책의 페이지에서 다시 측정한다.

### 함정: 문자 오프셋 계산 시 단어 사이 공백을 센다

단어를 이어 붙이며 볼드 구간을 문자 인덱스로 환산할 때, **단어 사이 공백
1칸을 문자 길이에 포함**해야 한다. 공백을 빼면 이후 모든 오프셋이 밀려
볼드가 엉뚱한 글자에 걸린다. 초기 구현에서 발생한 대표 버그다.

```python
def append_word(text, marks, w, bold):
    if text and not text.endswith(("-", "/")):
        text += " "
        marks.append(False)      # 공백도 문자 하나로 계산
    start = len(text)
    text += w
    marks.extend([bold] * len(w))
    return text
```

## 2. 소제목(헤딩) 검출

줄 단위로 다음을 함께 본다: **굵은 줄 + 줄 앞의 수직 간격(gap) + 짧은 길이 +
왼쪽 정렬**. `looks_heading(line)` 같은 술어로 거른다.

### 함정: `?`·`!`로 끝나는 질문형 제목

종결부호 목록에 `?`와 `!`를 넣으면 "Why are strikes unavoidable?" 같은
질문형 소제목이 **전부 탈락**한다. 이 책의 소제목 상당수가 질문형이라
치명적이었다. 종결부호는 `. , ; : ' " ) ’ ” … - —` 정도로 제한하고
`?`·`!`는 제목일 수 있게 허용한다.

```python
def looks_heading(t):
    if not (2 < len(t) < 52): return False
    if t[-1] in ".,;:'\")\u2019\u201d\u2026-\u2014": return False  # ?/! 제외
    if t.startswith(("\u2022", "-", "\u2013", "(")): return False
    ws = t.split()
    if not ws or len(ws) > 8: return False
    if ws[-1].lower().strip(".,;:!?") in STOP: return False
    return True
```

## 3. 블록인용 검출 — "들여쓰기=인용"이 아니다 (가장 큰 함정)

이 책은 **일반 문단도 첫 줄을 들여쓰기**한다. 그래서 "첫 줄이 오른쪽에서
시작하면 인용"이라는 규칙은 대량 오탐을 낸다(초기 362개 → 최종 61개).

올바른 판정:

- **문단 내 모든 줄의 시작 x가 본문 기준선보다 오른쪽**일 때만 블록인용.
- 첫 줄만 오른쪽이면 그것은 들여쓰기(일반 문단) 또는 리스트 hanging indent다.
- 리스트 항목(hanging indent)은 인용에서 제외한다.

본문 기준선(`unit`)은 줄 시작 x값의 **최빈값**으로 잡으면 안정적이다.

```python
unit = float(Counter(round(l["x"]/2)*2 for l in lines).most_common(1)[0][0])
# 인용 후보: 문단의 모든 줄이 unit보다 오른쪽
n   = len(lxs)
ind = sum(1 for x in lxs if x > unit+8)
is_quote = (n >= 1 and ind == n and min(lxs) > unit+6
            and len(text) >= 40 and len(text.split()) >= 5)
```

## 4. 번역문에 서식 적용 (병렬 서브에이전트)

검출 결과를 그대로 번역문에 끼워 넣지 말고, **청크별 서식 가이드**를 만들어
번역 담당 서브에이전트가 원문 대조로 마커를 삽입하게 한다.

- 검출 JSON → 토큰 정렬(`difflib.SequenceMatcher`)로 청크와 대응시킨다.
- `work/annot/guide_chunkNNNN.md`에 `## HEADINGS` / `## BLOCKQUOTES` /
  `## BOLD` 목록을 번호와 함께 적는다. 에이전트가 무엇을 적용했는지 보고하게 한다.
- 마커 규약: 소제목 `###`, 볼드 `**...**`, 블록인용 `>`.

## 5. 검증 — 텍스트 무손실

서식 마커를 넣고 빼도 본문 텍스트가 변하지 않아야 한다.

- 마커(`###`, `**`, `>`)를 제거한 결과가 백업 본문과 **문자 단위로 동일**한지
  청크마다 확인한다. 이 책에서는 84청크 전부 0건 불일치였다.
- 최종 EPUB/XHTML에서 `<strong>` 개수, `<blockquote>` 개수, 헤딩 개수를
  검출 JSON과 대조한다(실측: 볼드 611 span, 인용 60, 소제목 214).
