이 스킬은 현재 대화 컨텍스트와 코드베이스 이해를 바탕으로 PRD를 생성합니다. 사용자를 인터뷰하지 마세요 — 이미 알고 있는 내용을 종합하기만 하면 됩니다.

이슈 트래커와 분류 라벨 어휘가 제공되어 있어야 합니다 — 없으면 `/setup-matt-pocock-skills`를 실행하세요.

## 절차

1. 아직 하지 않았다면 저장소를 탐색하여 코드베이스의 현재 상태를 이해하세요. PRD 전반에 걸쳐 프로젝트의 도메인 용어집을 사용하고, 다루는 영역의 ADR을 존중하세요.

2. 기능을 테스트할 이음새(seam)를 스케치하세요. 기존 이음새를 새 이음새보다 선호해야 합니다. 가능한 가장 높은 수준의 이음새를 사용하세요. 새 이음새가 필요하면 가능한 가장 높은 지점에서 제안하세요.

이 이음새가 사용자의 기대와 일치하는지 확인하세요.

3. 아래 템플릿을 사용해 PRD를 작성한 후 프로젝트 이슈 트래커에 게시하세요. `ready-for-agent` 분류 라벨을 적용하세요 — 추가 분류는 필요하지 않습니다.

## 구현 결정 사항

내려진 구현 결정 사항의 목록입니다. 다음을 포함할 수 있습니다:

- 구축/수정될 모듈
- 수정될 모듈의 인터페이스
- 개발자의 기술적 명확화
- 아키텍처 결정
- 스키마 변경
- API 계약
- 특정 상호작용

특정 파일 경로나 코드 스니펫을 포함하지 마세요. 매우 빠르게 오래된 정보가 될 수 있습니다.

예외: 프로토타입이 산문보다 더 정밀하게 결정을 인코딩하는 스니펫(상태 머신, 리듀서, 스키마, 타입 형태)을 생성한 경우, 관련 결정 내에 인라인으로 포함하고 간략히 프로토타입에서 왔음을 표시하세요. 결정이 풍부한 부분만 남기고 — 작동하는 데모가 아닌 중요한 부분만 남기세요.
