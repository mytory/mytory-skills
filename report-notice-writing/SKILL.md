# 보고·공지 쓰기

읽는 사람이 앞뒤를 오가지 않고 한 번 읽어 이해하고, 자기가 할 일을 바로 알게 쓴다. 쓰는 사람이 덜 쓰는 것보다 읽는 사람이 덜 고생하는 것이 먼저다.

## 쓰기 전에

1. **누가 읽는가.** 그 사람이 이미 아는 것과 모르는 것을 구분한다. 우리 팀 내부 용어, 다른 팀 내부 이름, 코드 이름은 모른다고 본다.
2. **읽고 나서 무엇을 해야 하는가.** 알기만 하면 되는가(공지), 무언가를 해야 하는가(요청), 답을 줘야 하는가(질문). 섞여 있으면 나눠 적는다.

## 구성

- **맨 위에 핵심**: 읽는 사람이 할 일, 결론, 날짜. 여기까지만 읽어도 다음 행동을 정할 수 있어야 한다.
- 그다음 **이유와 배경**, 그다음 **세부**.
- 코드·SQL·명령은 그것이 **언제 실행되는지** 한 줄 적고 그 자리에 붙인다. 부록으로 떼어 놓고 "부록 A 참고"라고 하지 않는다.
- 분량을 줄여 달라는 요청을 받으면, 읽는 사람이 판단하는 데 필요 없는 세부를 뺀다. 남긴 문장을 압축하거나 참조로 바꿔 어렵게 만들지 않는다.

## 문장 규칙

- **참조로 줄이지 않는다.** "4절 참고", "2절 표의 대상 행", "위에서 말한 그것"을 쓰지 않는다. 그 자리에서 다시 풀어 쓴다. 같은 말을 두 번 쓰는 편이 낫다.
- **할 일은 요청으로 쓴다.** 상대가 해야 할 일을 "~하나요?"로 묻지 않는다. "~해야 합니다", "~해 주세요"로 쓴다. 이미 정한 일을 "언제 할까요?"라고 묻지 말고 "~합니다. 날짜를 알려 드리겠습니다"라고 쓴다. 정말 답이 필요한 것만 질문으로 남기고, 무엇을 알려 달라는지 분명히 쓴다("~한다면 알려 주세요").
- **요청마다 이유를 한 문장 붙인다.** 안 하면 무슨 일이 생기는지 적는다. 예: "이 값이 안 바뀌면 바뀐 주문을 모르고 취소할 수 있습니다."
- **모를 만한 말은 풀어 쓴다.** 내부 용어는 처음 나올 때 뜻을 적는다. 다른 팀 내부 이름(작업 번호, 내부 모듈명)은 쓰지 않는다. 쓰는 사람도 정확히 모르는 이름이면 더더욱 쓰지 않는다.
- **제목이 오해되지 않게 쓴다.** 제목·소제목이 질문처럼 보이거나 다른 뜻으로 읽히지 않는지 본다.
- 문장은 짧게, 한 문장에 한 가지. 숫자·날짜·이름은 정확히.

## 고치기 전후 예시

주문 서비스를 만드는 팀이 정산 팀에 보내는 공유 문서라고 가정한 예시다.

| 고치기 전 | 고친 뒤 | 문제 |
|---|---|---|
| 우리 쪽이 같은 컬럼을 먼저 만들 수 있습니다(5절). | 주문 서비스가 기동할 때 `settled_at` 컬럼을 이미 만들어 둡니다(이 문서 맨 아래 SQL). | 절 번호 참조 |
| 정산 배치 B-015·B-018은 컬럼이 이미 있어도 실패하지 않나요? | 컬럼을 만드는 SQL은 컬럼이 이미 있는지 확인하고 쓰세요. `ADD COLUMN IF NOT EXISTS`처럼 쓰면 됩니다. | 상대 팀 내부 이름, 요청을 질문으로 |
| 상태를 바꿀 때 `updated_at`도 함께 바꾸나요? | 상태를 바꿀 때 `updated_at`도 함께 바꿔야 합니다. 화면은 이 값으로 목록을 연 뒤 바뀌었는지 판단합니다. | 요청을 질문으로, 이유 없음 |
| 컬럼 이름 변경은 언제 할까요? | 컬럼 이름을 팀 관례에 맞춰 바꿔야 합니다. 조만간 바꾸고 날짜를 알려 드리겠습니다. 정산 쪽 코드도 새 이름으로 바꿔 주세요. | 정한 일을 질문으로 |
| 바뀐 주문은 집계를 다시 시작합니다. | 집계는 정산 배치가 주문별 결제 금액을 모으는 일입니다. 바뀐 주문은 모은 금액을 비우고 처음부터 다시 모읍니다. | 내부 용어 |
| 어떤 행을 초기화하나요? | 아래 행들을 초기화합니다. | 소제목이 질문처럼 보임 |
| 부록 A. 보류 SQL | 주문을 보류할 때 실행하는 SQL | "실행을 미룬 SQL"로 오해 |

## 다 쓴 뒤 점검

- [ ] 맨 위만 읽어도 할 일과 결론이 보이는가
- [ ] "n절", "위", "아래 표의 그것" 같은 참조가 남지 않았는가
- [ ] 상대가 할 일을 질문으로 쓴 문장이 없는가
- [ ] 요청마다 이유가 붙었는가
- [ ] 처음 보는 사람이 모를 용어·이름이 없는가(있다면 풀어 썼는가)
- [ ] 제목이 질문처럼 보이거나 다른 뜻으로 읽히지 않는가
- [ ] 코드·SQL마다 언제 실행되는지 적었는가
